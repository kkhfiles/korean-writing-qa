# 문서 종류별 적용

검사 명령의 `--profile`에는 아래 값을 사용한다.

| 값 | 대상 | 형식 | 추가 원칙 |
|---|---|---|---|
| `general` | 일반 업무 문서 | 구조형 | 정확하고 평이한 표현 우선 |
| `technical-report` | 기술 검토·설계·시험 보고 | 구조형 | 식별자 보존 · 원인과 결과 구분 · 기술용어 임의 번역 금지 |
| `executive-report` | 임원·의사결정 보고 | 구조형 | 결론·기한·상태 우선 · 내부 코드명만 단독 사용 금지 |
| `presentation` | 슬라이드 본문 | 구조형 | 한 화면의 정보량과 강조 제한 · 짧아도 조사에서 끊지 않음 |
| `presenter-notes` | 발표 대본·발표자 노트 | **산문형** | 압축 명사구를 풀고 말로 설명되는 문장 사용 · 계획과 진행 상태 구분 |
| `short-message` | 제품 안내·업무 메시지·안내 메일 | **산문형** | 인사말·접속사·완곡 표현을 늘리지 않고 필요한 행동 명시 |
| `ct-project` | CT 프로젝트 문서 | 구조형 | CT 관련 사용자 확정 표현 적용 |

### 표에 없는 종류를 만났을 때

**백서·설명문·블로그 글처럼 줄글로 읽히는 문서에는 전용 값이 없다.** 가까운 종류를 고르고 형식만 산문형으로 바꾼다.

| 문서 | 고를 값 | 형식 |
|---|---|---|
| 기술 백서 · 기술 설명문 | `technical-report` | 머리말에 `form: prose` |
| 일반 설명문 · 소개 글 | `general` | 머리말에 `form: prose` |

**전용 값을 안 만든 이유** — 새 값을 만들어도 규칙 묶음은 `general_it_business` 그대로라 검사 결과가 달라지지 않는다. 백서에서만 걸리는 규칙이 실제로 확정되면 그때 만든다.

## 구조 규칙의 적용 범위

- 라벨:값과 개조식 종결은 보고서·슬라이드처럼 찾아보는 문서에 적용한다.
- 설명문·발표자 노트·서술형 보고서에 개조식 규칙을 일괄 적용하지 않는다.
- 문서 종류가 섞이면 섹션별로 판단한다. 예를 들어 슬라이드 본문과 발표자 노트는 별도로 검사한다.

### 형식을 전역 문서 검사기에 넘기는 법

위 표의 형식이 **산문형**이면 전역 문서 검사기에 `--form prose`를 붙인다. 안 붙이면 개조식을 전제한 검사가 정상 문장을 지적한다 — 안내 메일 실측에서 「안녕하세요 …입니다.」와 「감사합니다.」까지 오류로 잡혀 아홉 건 전부 오탐이었다.

```powershell
python "$HOME/.claude/assets/doc-style-check.py" <문서> --form prose
```

- **문서 자신이 형식을 들고 다니게 하려면** 머리말에 `form: prose`를 적는다. 훅이 자동으로 검사할 때도 적용된다.
- **끄는 것**: 서술형 종결 · 제목 서술형 · 제목 명사형 위반 · 진입점 서술형·없음
- **그대로 도는 것**: 절단형 종결 · 모호한 지칭 · 스캔 가치 없는 라벨 · 평가 수식어 — 산문에서도 잘못이다
- **형식을 안 적었는데 산문으로 보이면** 검사기가 「형식 미표기」 주의 한 줄로 물어본다. 짐작해서 끄지 않는다 — 표와 라벨이 뼈대인 문서에 근거 문단이 붙은 형태를 산문으로 넘기면 정당한 지적이 조용히 사라진다.
