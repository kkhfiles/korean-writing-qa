# 핵심 한글 규칙

## 우선순위

1. 사용자가 이 문서나 같은 종류의 문서에 확정한 수정
2. 프로젝트에서 정한 용어와 문서 형식
3. 아래 공통 원칙
4. 외부 도구가 제안한 검증 전 후보

## 공통 원칙

각 원칙 뒤의 표시는 **누가 그것을 보는가**다. 이 구분이 없으면 검사 결과가 비어 있을 때 그 원칙까지 지켜졌다고 잘못 읽는다.

- `[스킬]` 스킬 검사기가 잡는다 · `[전역]` 전역 문서 검사기가 잡는다 · `[사람]` 검사기가 못 잡으므로 직접 읽고 판단한다

실측 기준으로 열한 개 중 검사기가 보는 것은 넷이고, 그중 셋은 일부만 본다.

- **압축한 명사구 풀기** `[사람]`: `곳`·`구간`·`부분`이 실제 대상이나 행위를 숨기면 과정·항목·단계·시점을 밝혀 쓴다.
- **막연한 비유 줄이기** `[스킬: 경로]` `[전역: 자리]` `[사람: 나머지]`: 실제 파일 위치가 아닌 `경로`, 실제 좌석이 아닌 `자리`, `세우다` 같은 비유는 구체적인 행위로 바꾼다. **모임도 `자리`로 부르지 않는다**(2026-09-04) — 회의·세미나·간담회 중 실제로 무엇인지 쓴다. 「의견을 받는 자리」는 「의견을 수렴하는 회의」로. 모임 뜻을 예외로 두었더니 화면의 입력 칸을 가리키는 「묻는 자리」까지 통과했다.
- **지어낸 명사구 걸러내기** `[전역: 판·창·결]` `[사람: 값·축·층]`: 관형형 어미(`-는`·`-은`·`-을`) 뒤에 뜻이 옅은 명사를 붙여 새 말을 만들지 않는다. `판`·`창`·`값`·`결`·`축`·`층`이 자주 걸린다. 앞의 셋은 실문서 1,161개에서 정당하게 쓰인 적이 없어 전역 검사기가 주의로 낸다. 뒤의 셋은 이 분야에서 그 명사가 혼자 서므로(코드가 계산하는 `값` · 못 보는 `축` · 읽는 `층`) 사람이 읽고 가른다. 판정 기준은 **그 명사가 혼자 서는가**다 — 「모으는 창」의 `창`은 떼어 놓으면 무엇인지 말할 수 없고, 「걸린 시간」의 `시간`은 말할 수 있다. 한 낱말로 붙어 굳은 말(`편집창`·`바둑판`)과 실물은 그대로 둔다. 바꿔 쓸 말이 없으면 명사구를 만들지 말고 문장을 서술로 편다.
- **실무 행위 밝히기** `[사람]`: `풉니다`·`돕습니다`·`진행합니다`처럼 범위가 넓은 동사는 설계·개발·검증·산출·수행 등 실제 행위로 바꾼다. 문맥이 없으면 추측하지 않는다.
- **계획과 결과 구분하기** `[사람]`: 개발 중·계획·완료를 원문 근거대로 적는다. 자연스럽게 보이려고 계획을 결과로 바꾸지 않는다.
- **번역투 줄이기** `[사람]`: `~에 대한`, 불필요한 피동, 영어식 명사 나열, 같은 접속사의 반복을 줄인다.
- **불필요한 영어 줄이기** `[사람]`: API·필드·모듈·제품의 실제 이름은 보존한다. 일반 설명은 독자가 아는 한국어를 우선한다. 다음 둘은 지적하지 않는다.
  - **업계에 굳은 외래어**: 그 분야 사람들이 한국어처럼 쓰는 말은 바꾸지 않는다. `포지셔닝`·`리팩터링`·`파이프라인`이 그렇다. 판정 기준은 사전 등재가 아니라 그 문서의 독자가 그 말로 소통하는지다.
  - **뜻이 같은 대체어가 없는 말**: 바꾸면 가리키는 범위가 달라지는 말은 원문을 유지한다. `에이전틱`을 `자율 수행`으로 바꾸면 뜻이 달라진다. 대체어를 먼저 정하고 그것이 원어와 같은 것을 가리키는지 확인한 뒤에 지적한다.
- **기계적 병렬 피하기** `[사람]`: 모든 문장을 같은 길이와 같은 종결로 맞추지 않는다. 내용 관계에 맞게 문장 길이를 조절한다.
- **장식보다 정보 우선하기** `[전역: 평가 수식어·굵게 중복]` `[사람: 이모지]`: 뜻 없는 이모지·굵게·평가 수식어를 줄인다. 측정값이나 구체적인 기능으로 바꿀 수 없는 자평은 삭제한다.
- **군더더기 지우기** `[사람]`: 접속사·형용사·부사를 지운 뒤 뜻이 그대로면 뺀다. 같은 내용을 표와 본문에 반복하지 않는다.
- **소리 내어 읽기** `[전역: 절단형 종결]` `[사람: 나머지]`: 조사에서 끊기거나 서술어가 사라진 문장, 한 번에 이해되지 않는 긴 문장을 고친다.

## 사용자가 확정한 대표 수정

문맥을 봐야 고칠 수 있는 교정은 검사기가 못 잡는다. 그래서 여기에 적는다 — **이 표가 그 교정들이 실제로 읽히는 유일한 곳**이다.

**적용 조건을 먼저 읽는다** — 여기 실린 것은 낱말 대 낱말 치환이 아니다. 같은 낱말이라도 조건에 안 맞으면 고치지 않는다.

| 수정 전 | 수정 후 | 적용 조건 |
|---|---|---|
| 제품화 경로 | 제품화 단계 | 일반 IT 업무 문서 |
| CT를 다시 세우는 부분 | CT 재개발이 필요한 항목 | CT 프로젝트 문맥 |
| 갈래는 둘 | 크게 두 가지로 나뉘는데 | 발표자 노트 · 뒤에 분류명이 이어지는 경우 |
| 검증은 반복해서 도는 일 | 반복해서 수행하는 작업 | 조건이 앞뒤 문장에 남아 있는 경우 |
| 사람이 가장 많이 붙는 곳 | 공수가 많이 필요한 과정 | 발표자 노트 · AI 적용 계획이 뒤 발화에 남아 있는지 확인 |
| 막대가 상반기 실측입니다 | 현재 보여드리는 내용이 상반기 결과이며 | 발표자 노트 · 화면을 가리키며 말하는 경우 · 다음 발화로 이어짐 |
| 뒤의 것은 커버리지를 더 올립니다 | 더 높은 커버리지를 달성할 수 있도록 개발하고 있습니다 | 발표자 노트 · 개발 중인 것이 확인된 경우에만 진행형 |
| 가치가 둘 나옵니다 | 중요한데, 두 가지 이유 때문입니다 | 발표자 노트 · 무엇이 중요한지와 두 이유가 앞뒤 발화에 있는 경우 |
| 로컬 실행 환경 구축 기능 추가 | 로컬 실행 환경을 구축하는 기능 추가 | 조사 없이 명사만 이어 붙어 무엇이 무엇을 하는지 사라진 경우 |
| 에러 | 오류 | 한글 대체어가 이미 널리 쓰이는데 영문을 한글 발음으로 적은 경우 |
| 최초 버전 인도 | 최초 버전 공급 · 최초 버전 전달 | 「인도」가 나라 이름으로 읽힐 수 있는 문맥 |
| 브랜드 재정립 | 무엇을 어떻게 바꿨는지 적음 | 재정립·고도화처럼 한 일이 숨는 말 · 원문에 근거가 있을 때만 |
| 시드 목록 | 시드(조사 대상으로 미리 정한 도구) 목록 | 내부 용어가 문서에서 처음 나오는 경우 · 두 번째부터는 그대로 |
| AI 조립 라인 | AI 조립 라인(AI Assembly Line) | 옮긴 고유명·제품명 · 원문이 확인되는 경우에만 병기 |

## 외부 참고 자료에서 채택한 원칙

- `korean-report-skills`: 동사 하나를 금지하지 않고 주어와 술어의 결합을 본다. 실제 식별자와 일반 설명을 구분한다.
- `fluent-korean`: 생략된 문장 성분을 복원하고, 분야에서 굳지 않은 비유를 실제 행위로 바꾼다.
- `humanize-korean`: 내용·수치·인용·장르를 보존하고, 번역투·영어 과다·기계적 병렬·균일한 리듬을 문맥으로 판단한다.
