# eval-008 — 두 실행기의 검사 덮개

**Codex 가 절반만 덮여 있었음 · 고친 뒤 범위 덮개 실측** — 의도한 제외를 빼면 100%

## 물은 것

**목표** — 이 PC 에서 AI 가 만드는 모든 문서 산출물이 검사 통과한 한글

**그 목표를 재는 수단이 없었음** — 2층 이행율은 재면서 1층 덮개는 안 쟀다.

## 고치기 전 — 실행기별로 갈려 있었음

| | Claude Code | Codex |
|---|---|---|
| 스킬 검사기 · 확정 표현 8건 | 돎 | 돎 |
| **구조 검사기** · 오류의 대부분 | 돎 | **안 돎** |
| **발행 직전 점검** | 돎 | **없음** |

**까닭은 사본** — `codex-hook-adapter.py` 가 확장자·제외 목록을 따로 들고 스킬 검사기만 직접 불렀다. 전날 고친 게이트 수정(실패를 알리게 한 것)도 Codex 에는 안 갔다.

## 고친 방향 — 어댑터는 옮기는 일만 담당

| 담당 | 무엇 |
|---|---|
| 어댑터 | Codex payload 에서 경로 뽑기 · `apply_patch` 패치 본문 파싱 |
| **훅 한 곳** | 확장자 · 제외 목록 · 발행 명령 판정 · 어느 검사기를 어떻게 부를지 |

**「같은 훅을 공유」로는 안 됐음** — `shared` 모드가 Codex payload 를 그대로 넘기는데, 훅은 `hook_event_name` 으로 먼저 가르고 Codex payload 에는 그 값이 없다. 붙여도 조용히 아무것도 안 돈다.

## ⛔ 이 계기판이 답하지 못하는 것 둘

**「실제로 돌았나」** — 깨끗한 문서에서는 훅이 조용해서, 기록만으로는 돌아서 조용한 것과 안 돈 것이 안 갈린다. 답하는 것은 **범위**뿐이다. 실제로 도는지는 시험이 지킨다.

**Codex 쪽 수치** — 세션 기록이 Claude Code 것만 남아 이 계기판이 못 본다. Codex 덮개는 `tests/test_codex_uses_the_same_gate.py` 가 지킨다.

## 재검토에서 더 고친 것 셋 (같은 날)

**① 배치·예약 세션에서도 시험을 돌릴 뻔함** — SessionStart 훅 넷이 다 하는 `CLAUDE_BATCH_MODE`·`CLAUDE_SCHEDULED` 조기 종료가 새 훅에만 빠져 있었다. 자동으로 도는 세션이 9초를 쓴다.

**② 파일마다 프로세스를 띄우고 있었음** — 어댑터가 거르지 않고 넘겨 소스 20개짜리 패치가 0.89초를 썼다. 훅의 판정 함수를 빌려 미리 거르게 바꿔 **0.06초**. 목록을 베끼지 않았으므로 정의는 여전히 한 벌이다.

**③ 처음 잰 성능이 틀렸음** — 없는 파일 20개로 재고 「0.16초, 문제 없음」이라 했는데, 없는 파일은 애초에 걸러진다. **증상이 나는 모양(실재하는 파일)으로 다시 재서** 0.89초를 봤다.

## ✅ Codex payload 는 운영 기록으로 확인됨

**옛 어댑터의 출력이 Codex 세션 기록 3개에서 74회** 나온다(8/24 · 9/2). 훅이 실제로 불리고 경로 뽑기가 진짜 payload 에서 동작한다는 뜻이다. 시험이 넣는 필드가 운영에서 쓰이는 그 필드다.

**⚠️ 아직 못 잰 것** — 새로 붙인 발행 시점(`PreToolUse` Bash). 그 경로로 Codex 세션이 지나간 기록이 아직 없다.
