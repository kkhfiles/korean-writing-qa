# 실제 발행 문서로 미탐 찾기 — 사전 기록

**목적** — 지난주 이 PC에서 발행 게이트(2층 판정)를 거친 실제 문서에 im-not-ai 윤문을 돌려, 게이트를 통과하고도 남은 결함을 찾음

- **잰 날**: 2026-10-26
- **입력**: 2026-10-20부터 10-23 사이 판정기 기록이 있는 문서 가운데 한글 8천 자 이하 5편
  - 주간보고 한 장 요약과 요약본, 백서 변경 노트, DevRel 회의록, 이 저장소 `CONTRIBUTING.md`
  - 4만 자 세미나 개요와 다른 사람이 쓴 백서 원고는 뺌
- **방법**: 2026-10-23 회차와 같은 실행기(`runs/imnotai-miss-mining-20261023/run.py`)와 같은 판정 기준
- **본문 보관**: 저장소 밖 작업 폴더에만 두고 저장소에는 집계만 둠
- **과금**: 모두 구독

## 미리 정한 판정

- **미탐 후보**: im-not-ai가 바꾼 원문 줄 중 같은 줄에 1층 지적과 2층 지적이 모두 없는 줄
- **서식만 바꾼 줄**: 묻지 않음(2026-08-28 결정으로 검사기 범위 밖)
- **사람 판정**: 문장을 고친 후보마다 「원문이 잘 쓴 업무 문서에서 결함인가」
- **멈춤 규칙**
  - 결함 판정이 0건이면 실제 문서 미탐 찾기를 정기 점검으로 두지 않음
  - 1건 이상이면 갈래별로 규칙에 반영하고 다음 회차를 사용자와 정함
