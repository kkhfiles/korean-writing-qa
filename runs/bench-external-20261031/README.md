# 다른 한국어 검사·교정 도구와의 비교 측정

**품질, 속도, 비용을 같은 입력으로 비교한 기록** — 결과를 보기 전에 정한 방법과 판정 기준(이 절)을 먼저 커밋하고, 결과는 아래 「결과」 절에 덧붙임

- **측정 기간**: 2026-10-31 ~ 2026-11-01, `plain-flash` 는 2026-11-02 추가 측정
- **요청**: 사용자(2026-10-30) — 다른 한국어 검사·교정 도구와 비교해 이 저장소의 강점을 품질, 성능, 비용 모두 객관적 수치로 제시
- **본문 보관**: 시험 글과 도구 출력은 저장소 밖(`~/.local/share/korean-writing-qa/bench-external/`)에 두고 이 기록에는 수만 적음

## 지표

- **회수율**: 삽입한(D2) 또는 표시된(D1) 결함 구간과 겹치는 지적이 있는 비율. 지적이 인용한 원문 구간이 결함 구간과 두 글자 안으로 겹쳐야 함
  - `l1` 은 같은 입력에 늘 같은 출력을 내므로 깨끗한 원문 대비 새로 생긴 지적만 셈
  - 교정형 도구(`kiwi-space`, `kobart-gec`)는 바꾼 구간으로 셈
- **교정 정확도**(D1): 지적의 수정안을 적용한 문장이 정답 문장과 글자까지 같은 비율
- **깨끗한 글 지적 밀도**: 결함을 삽입하지 않은 원문(D1 정답 문장, D2 원문)에서 한글 1천 자당 지적 수. 원문에도 실제 결함이 있을 수 있어 「오탐률」이 아니라 「읽는 사람이 볼 지적 부담」으로 부름
- **속도**: 한글 1천 자당 걸린 초(모델은 호출 대기 포함)
- **비용**: 한글 1천 자당 입력 토큰과 출력 토큰, 그리고 Claude는 SDK가 산출한 API 단가 환산 금액(청구액 아님). GPT와 Gemini는 이 PC에서 단가를 확인할 자료가 없어 토큰 수만 적고, agy처럼 토큰 수를 제공하지 않으면 주고받은 글자 수를 적음

## 판정 기준 (결과 전에 정함)

- **차이 주장 조건**: 문서 단위 부트스트랩(1만 회) 95% 신뢰구간이 0을 포함하지 않을 때만 「높다」, 「낮다」로 적음. 그렇지 않으면 「차이 판정 불가」
- **갈래별로 따로 보고**: 합계 하나로 순위를 매기지 않음. F5는 이 저장소 규칙이라 합계에서 뺀 값도 함께 적음
- **불리한 결과도 그대로 적음**: D1처럼 이 저장소의 영역이 아닌 시험에서 지는 결과도 본문에 남김
- **1회 측정**: 모델 출력은 실행마다 달라지므로 각 시스템을 한 번씩 실행한 결과임을 적음(결과를 확인한 뒤 추가한 D4 시험만 2회 측정)

## 결과

**요약** — 2층 판정기의 일반 결함 회수율은 같은 모델에 교정만 요청한 것과 차이를 판정할 수 없고(보정 회수율과 엄격 기준 회수율은 `l2` 가 `plain-claude` 보다 낮음), 비용은 1.5~2.4배임. 사용자가 지적한 업무 글 표현을 삽입한 시험([D4](#d4-사용자가-지적한-표현-이-저장소의-본래-영역))에서는 회수율이 `l2` 97%, `plain-claude` 26%임. 판정기 지적을 Opus가 그대로 반영한 문서는 고치지 않은 초안보다 낮게 평가됨

- **수치 원본**: [result.json](result.json) — 표의 값은 이 파일에서 옮김(정밀도와 고쳐 쓰기 표는 `tables.py` 가 생성하고, `verify_numbers.py` 가 D1, D2, 정밀도, D4 표의 값을 원본과 대조함)
- **차이 판정**: 「높음」, 「낮음」은 문서 단위 부트스트랩 95% 신뢰구간이 0을 포함하지 않은 것만 적음
