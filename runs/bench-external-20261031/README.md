# 다른 한국어 검사·교정 도구와의 비교 측정

**품질, 속도, 비용을 같은 입력으로 비교한 기록** — 결과를 보기 전에 정한 방법과 판정 기준(이 절)을 먼저 커밋하고, 결과는 아래 「결과」 절에 덧붙임

- **측정 기간**: 2026-10-31 ~ 2026-11-01
- **요청**: 사용자(2026-10-30) — 다른 한국어 검사·교정 도구에 비해 강점을 객관적 수치로, 품질과 성능과 비용 모두
- **본문 보관**: 시험 글과 도구 출력은 저장소 밖(`~/.local/share/korean-writing-qa/bench-external/`)에 두고 이 기록에는 수만 적음

## 비교 대상

| 이름 | 무엇 | 부르는 방법 |
|---|---|---|
| `l1` | 이 저장소 1층 검사기 | `assets/doc-style-check.py --no-rules`, 머리말 `form: prose` |
| `l2` | 이 저장소 2층 판정기 | `scripts/judge_layer2.py --backend claude --model opus`, 기록 폴더를 실행마다 따로 둠 |
| `plain-claude` | Claude Opus에 교정만 부탁 | 같은 모델, 일반 교정 지시문(`systems.py` 의 `PLAIN_SYSTEM`) |
| `plain-gpt` | GPT 6 Astra에 교정만 부탁 | 같은 지시문, Codex 구독 |
| `plain-argon` | Gemini 4 Argon에 교정만 부탁 | 같은 지시문, agy |
| `imnotai-claude` | im-not-ai humanize-korean 2.3.2 규칙 | 그 플러그인의 `quick-rules.md` 를 지시문으로 Opus 호출(플러그인 흐름 전체가 아니라 규칙만 빌림) |
| `kiwi-space` | Kiwi 0.23 띄어쓰기 교정 | `Kiwi.space` |
| `kobart-gec` | KoBART 문법 교정 모델 | Hugging Face `Soyoung97/gec_kr`, CPU |

- **뺀 것**: 부산대(바른한글)와 네이버 맞춤법 검사기 — 사용자 결정(2026-10-31)으로 자동 비교에서 제외
- **뺀 것**: hunspell 한국어 사전 — 순수 파이썬 구현이 사전을 잘못 읽고(「회의」도 철자 오류로 냄), 네이티브 바인딩은 이 PC에 컴파일러가 없어 설치 안 됨
- **뺀 것**: Kor-Native 시험 세트 — 내려받으려면 구글 계정으로 양식을 내야 함
- **같은 지시문**: 세 단순 교정 요청은 같은 지시문을 쓰고 이 저장소 규칙을 싣지 않음

## 시험 세트

| 이름 | 무엇 | 정답 출처 | 이 저장소에 유리한지 |
|---|---|---|---|
| D1 K-NCT | 공개 문법 교정 시험 세트(3,000문장, 띄어쓰기·문장 부호·숫자·맞춤법 오류)에서 오류 갈래별 100문장 | 시험 세트 제작자 | 불리함 — 맞춤법 도구의 영역 |
| D2 공개 글 결함 심기 | 정책브리핑 정책뉴스 40편(공공누리 제1유형)에 결함 다섯 갈래를 한 편에 하나씩 심음 | 심은 위치 | 갈래마다 다름(아래) |
| D3 AI 초안 고쳐 쓰기 | 공개 주제로 AI가 쓴 업무 문서 초안을 도구마다 고친 결과 | 다른 회사 모델 셋의 블라인드 비교 | 판정자 편향을 표로 따로 보임 |

**D2 결함 갈래** — 갈래마다 정답 기준을 밖에서 빌림

| 갈래 | 기준 | 심는 방법 |
|---|---|---|
| F1 맞춤법과 띄어쓰기 | 한글 맞춤법 | 정해진 치환(됐→됬, 할 수→할수 등) |
| F2 공공언어 바로 쓰기 | 국립국어원 공공언어 지침(이중 피동, 번역투, 중복 표현, 주술 호응 등) | GPT(sol)가 지정한 문장에 지정한 결함만 넣음 |
| F3 AI 티 | im-not-ai 분류(상투 문형, 대구, 결말 공식 등) | GPT(sol) |
| F4 문맥 결함 | 앞뒤 사실 불일치(숫자, 날짜, 주체) | GPT(sol) |
| F5 업무 문서 형식 | 이 저장소 규칙(절단형 종결, 띄어 쓴 가운뎃점, 모호한 지칭 등) | 정해진 치환(이 저장소에 유리해 따로 보고) |

- **심는 모델을 GPT로 둔 까닭**: 판정기와 같은 회사 모델이 심으면 이 저장소에 유리한 쪽으로 치우칠 수 있어, 치우침이 생긴다면 불리한 쪽으로 가게 함

## 지표

- **회수율**: 심은(D2) 또는 표시된(D1) 결함 구간과 겹치는 지적이 있는 비율. 지적이 인용한 원문 구간이 결함 구간과 두 글자 안으로 겹쳐야 함
  - `l1` 은 출력이 결정론이라 깨끗한 원문 대비 새로 생긴 지적만 셈
  - 교정형 도구(`kiwi-space`, `kobart-gec`)는 바꾼 구간으로 셈
- **교정 정확도**(D1): 지적의 수정안을 적용한 문장이 정답 문장과 글자까지 같은 비율
- **깨끗한 글 지적 밀도**: 결함을 심지 않은 원문(D1 정답 문장, D2 원문)에서 한글 1천 자당 지적 수. 원문에도 실제 결함이 있을 수 있어 「오탐률」이 아니라 「읽는 사람이 볼 지적 부담」으로 부름
- **속도**: 한글 1천 자당 걸린 초(모델은 호출 대기 포함)
- **비용**: 한글 1천 자당 입력 토큰과 출력 토큰, 그리고 Claude는 SDK가 낸 API 단가 환산 금액(청구액 아님). GPT와 Gemini는 이 PC에서 단가를 확인할 자료가 없어 토큰 수만 적고, agy처럼 토큰 수를 주지 않으면 주고받은 글자 수를 적음

## 판정 기준 (결과 전에 정함)

- **차이 주장 조건**: 문서 단위 부트스트랩(1만 회) 95% 구간이 0을 넘지 않을 때만 「높다」, 「낮다」로 적음. 그렇지 않으면 「차이 판정 불가」
- **갈래별로 따로 보고**: 합계 하나로 순위를 매기지 않음. F5는 이 저장소 규칙이라 합계에서 뺀 값도 함께 적음
- **불리한 결과도 그대로 적음**: D1처럼 이 저장소의 영역이 아닌 시험에서 지는 결과도 본문에 남김
- **1회 측정**: 모델 출력은 실행마다 흔들리므로 각 시스템을 한 번씩 돌린 결과임을 적음
