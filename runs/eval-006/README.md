# eval-006 — 2층이 실제로 도는 비율

**운영 중 2층 호출 비율과 그것을 올리려 붙인 장치의 기준선** — 효과 판정은 아직 못 함 · 며칠 뒤 재측정

## 재는 이유

**2층 회수율 0.771 = 「돌았다면 잡았을 값」** — 실제로 도는 비율을 안 재면 그 숫자가 운영 성능인 것처럼 읽힌다.

## 붙이기 전 실측 (최근 14일 · 이 저장소 세션 제외 · 2026-09-01 다시 잼)

| 단계 | 값 | 뜻 |
|---|---|---|
| 발행 도구 호출 | 244회 | 훅이 실제로 발행 게이트를 건 호출 |
| 안내 발화 | 52회 · **21.3%** | 발행할 때 2층을 부르라는 말이 뜬 비율 |
| 스킬 호출 | 2회 · **3.8%** | 안내가 떴을 때 실제로 부른 비율 |

**한글 문서를 파일에 쓴 세션 55개 중 스킬을 부른 세션은 2개(3.6%)**

**⚠️ 처음 적었던 8.3%는 틀린 값** — 분모에 조회·소스 읽기가 섞여 627로 부풀었음 · 아래 「측정기가 네 번 틀렸던 것」 참조

## 21.3%가 나온 원인

**안내가 1층 지적 목록의 머리줄에 있었음** — 1층이 아무것도 못 잡으면 목록 자체가 안 나오고 안내도 함께 사라졌다. 발행되는 문서 다섯 중 넷이 1층에 안 걸린다.

**앞서 「1층 회수율 0.057이니 안내도 그만큼」이라 적은 것은 틀림** — 회수율(참 문제 중 잡는 비율)과 발화율(문서 중 한 건이라도 걸리는 비율)은 다른 수치다. 두 숫자를 인과로 이은 것이 잘못이었다.

**1층이 조용한 때 = 2층이 가장 필요한 때** — 바로 그때 안내가 없었다.

## 고친 것 (2026-08-31)

**안내를 발행 경로로 옮김** — 1층 발화와 무관하게 항상 냄 · `~/.claude/hooks/doc-style-gate.py`

| 항목 | 값 |
|---|---|
| 묶는 단위 | 문서마다 세션에 한 번 |
| 예상 빈도 | 하루 **2.1건** · (세션, 문서) 짝 30개 / 14일 |
| 쓰는 순간 | 안 냄 — 초안까지 태우면 사람이 알림을 끔 |
| 안내에 담은 것 | 실측 회수율 1층 0.057 대 2층 0.771 |

**만들다 훅을 한 번 죽였음** — 상태 파일에 중첩 사전을 넣어 만료 정리가 터졌다. **훅은 실패해도 조용해서** 화면에는 「안내가 안 뜬다」로만 보였다. 상태 구조와 종료 코드를 시험으로 잡았다.

## 측정기가 네 번 틀렸던 것

| 무엇 | 어떻게 틀림 | 잰 값 |
|---|---|---|
| 표시가 짧았음 | 「발행 직전」 넉 자로 찾아 그 문구를 **논의한 글**까지 셈 | 발화율 208% |
| 자기 세션을 셌음 | 이 시스템을 만드는 세션이 문구를 계속 인용 | — |
| **발행의 정의를 자기가 들고 있었음**(9/1) | 조회(`notion.py children`)와 소스 읽기(`grep … notion.py`)까지 발행으로 셈 · 훅은 셋 다 발행으로 안 봄 | 분모 627 → 244 · 발화율 8.3% → **21.3%** |
| **경계를 날짜로 잡았음**(9/1) | 훅을 고친 것은 8/31 07:56 UTC인데 경계가 그날 자정 · 네 시간 **전** 활동이 「붙인 뒤」로 들어감 | 「발행 8건에 안내 0건」 · 실제로는 발행 0건 |

**앞의 둘은 「자기 활동을 성과로 센다」** · **뒤의 둘은 「정의를 두 벌로 들고 있다」** — 뒤엣것은 이 저장소가 훅의 접기 규칙에서 이미 한 번 겪은 실패다.

**뒤의 둘이 특히 나빴던 이유** — 「발행 8건에 안내 0건」은 **고친 장치가 안 먹혔다**로 읽힌다. 실제로는 고친 뒤 발행이 한 건도 없었다. 그 오독대로 갔으면 멀쩡한 훅을 다시 뜯었다.

**고침** — 발행 판정을 훅의 `targets()`에 물어보게 바꿈 · 경계를 커밋 시각으로 · 시험 5건과 돌연변이 3건으로 고정
