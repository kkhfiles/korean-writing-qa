# im-not-ai 윤문으로 이 저장소의 미탐 찾기 — 사전 기록

**목적** — im-not-ai가 고쳐 쓴 줄 가운데 이 저장소의 1층 검사기와 2층 판정이 둘 다 지적하지 않은 줄을 모아, 검사기에 더할 규칙 후보를 찾음

- **잰 날**: 2026-10-23
- **입력**: `data/raw/diagnostic-002` 의 AI 업무 보고서 5편(doc-002, doc-004, doc-005, doc-015, doc-016)
  - 종류 다섯 가지, 한글 1,800~4,500자
  - 머리말은 떼고 두 도구에 같은 글을 줌
- **im-not-ai 쪽**: 2.3.2 정밀 경로의 계약을 그대로 따름
  - 결정론 입력 가공(`prepare_monolith_input.py --genre report`)
  - 진단 에이전트 정의와 `diagnosis-rules.md` 로 진단문 작성
  - 진단문을 붙인 입력을 윤문 에이전트 정의와 `quick-rules.md` 로 고쳐 씀
  - Opus 단발 호출 2회, 도구 대신 파일 내용을 글로 넣음
- **이 저장소 쪽**: `doc-style-check.py` 전 갈래와 `judge_layer2.py`(Opus, 기본 설정)
- **과금**: 모두 구독(`LLM_PLAYBOOK_BILLING=subscription`)
- **지시 파일**: 어느 호출에도 안 실림(단발 메시지 호출)
- **본문 보관**: 저장소 밖 작업 폴더에만 두고 저장소에는 집계만 둠

## 미리 정한 판정

- **미탐 후보**: im-not-ai가 바꾼 원문 줄 중 같은 줄에 1층 지적과 2층 지적이 모두 없는 줄
- **사람 판정**: 미탐 후보마다 「원문이 잘 쓴 업무 문서에서 결함인가」를 사용자가 가름(고친 문장이 더 나은지는 묻지 않음)
- **판정 결과의 쓰임**
  - 결함으로 판정된 줄: 갈래로 묶어 규칙 후보로 올림(`fix-korean-finding` 절차)
  - 결함이 아닌 줄: im-not-ai의 업무 문서 과윤문으로 기록
- **멈춤 규칙**
  - 5편에서 결함 판정이 0건이면 im-not-ai 윤문에서 더 캐지 않음
  - 1건 이상이면 표본을 넓힐지 사용자와 정함
- **흔들림**: 각 호출 1회라 재현 변동은 안 잼(결과는 후보 목록으로만 쓰고 비율로 일반화하지 않음)
