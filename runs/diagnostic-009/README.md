# diagnostic-009 — 「명사로 굳힌 서술」을 결정 규칙으로 잡을 수 있나

**결론: 못 잡음 · 결정 규칙 쪽 닫음** — 개조식 라벨이 곧 명사 나열이라 같은 모양임 · 판단 층 소관

## 이 갈래를 고른 이유

**실측 참 문제 4건 중 1층이 0건** (`runs/eval-005`) — 불필요한 영어(13건) 다음으로 큰 미탐 갈래

**모양이 구조적이라 잡힐 것 같았음** — 낱말 목록이 아니라 「조사 없이 이어진 명사 덩어리」라는 구조다. 「불필요한 영어」와 달리 셀 수 있다.

**사용자가 확정한 교정이 이미 있음** — 「로컬 실행 환경 구축 기능 추가」 → 「로컬 실행 환경을 구축하는 기능 추가」 · 조건은 「조사 없이 명사만 이어 붙어 무엇이 무엇을 하는지 사라진 경우」

## 만든 것

**두 임계를 건 탐지기** — 조사·어미로 끊기지 않은 한글 토큰 덩어리를 세고, 그 안에 「하다」가 붙는 행위 명사(구축·추가·수행·고도화 등 84낱말)가 몇 개인지 본다.

| 시료 | 덩어리 | 행위 명사 |
|---|---|---|
| 로컬 실행 환경 구축 기능 추가 | 6 | 3 |
| 컨텍스트 압축 및 세션 리셋 주기적 수행 | 7 | 3 |
| 플랫폼 기능 고도화 발표 | 4 | 2 |
| 새 세션 진입 시 첫 메시지 (정상) | 4 | 0 |
| 기능 추가 (정상) | 2 | 1 |

## ★ 구조적으로 안 되는 이유

**개조식 라벨이 곧 명사 나열임** — 이 검사기가 강제하는 문체가 바로 그 모양이다. 「버그 수정 반영 확인」은 정상 값이고 「로컬 실행 환경 구축 기능 추가」는 잘못인데, **표면이 같다.**

**가르는 신호가 표면에 없음** — 앞엣것은 한 갈래로 이어지는 수식이고, 뒤엣것은 명제 둘(환경을 구축한다 · 기능을 더한다)을 눌러 붙인 것이다. 그 차이는 뜻이지 모양이 아니다.

**세 번째로 닫힌 결정 규칙 경로**

| 갈래 | 닫힌 이유 |
|---|---|
| 불필요한 영어 | 사용자도 「이슈」·「컨펌」·「타깃」을 씀 · 문맥이 가름 |
| 「~에 있어」 | 「저장소에 있어 접근이 안 된다」와 안 갈림 |
| **명사로 굳힌 서술** | **개조식 라벨과 표면이 같음** |

**셋 다 판단 층 소관** — 폐기가 아니라 자리를 옮긴 것이다.

## 이 결과가 말해 주는 것

**1층 회수율 0.057의 천장이 구조적임** — 참 문제 35건 중 결정 규칙으로 못 잡는 갈래가 불필요한 영어 13 + 명사로 굳힌 서술 4 = **17건(49%)**이다. 규칙을 더 만들어도 이 절반은 안 잡힌다.

**그래서 다음 지렛대는 2층이 실제로 도는 비율** — 지금 3.6% (`runs/eval-006`)
