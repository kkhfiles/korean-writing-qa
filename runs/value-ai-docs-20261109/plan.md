# 사전 기록 — AI 투 교정의 품질과 반복 수정 효율 (2026-11-09)

**물음** — 사용자가 정리한 가치(2026-11-09) 가운데 둘을 잰다

- **AI 투와 업무 낱말 교정** — 같은 규칙을 넣은 단순 요청이나 널리 알려진 AI 글 윤문 도구(im-not-ai)보다 이 검사기가 사용자 기준에 맞게 고치나
- **반복 수정 효율** — 「규칙을 넣고 통째로 다시 고쳐 달라는 요청을 반복」하는 흐름보다 회차, 비용, 시간이 나은가

맞춤법과 일반 결함은 재지 않는다(사용자 정리 「맞춤법 검사기는 아님」).

## 고치는 흐름

| 이름 | 하는 일 | 모델 |
|---|---|---|
| plain | 「자연스러운 업무 문서로 다듬어 달라」 한 번 | Claude Opus |
| rules | 판정기와 같은 판단 규칙 전문을 시스템 프롬프트로 주고 「규칙에 맞게 고쳐 달라」 한 번 | Claude Opus |
| imnotai | im-not-ai 2.3.2 정밀 경로(진단 뒤 윤문) — `runs/imnotai-miss-mining-20261023/run.py` 와 같은 호출 | Claude Opus |
| rules_loop | rules 를 「변경 없음」이 나올 때까지 반복, 최대 5회 | Claude Opus |
| checker | 이 검사기 가성비 단계 — 판정, 수정안 적용, 고친 줄만 다시 판정, 끝날 때까지(세션 흉내 `bench_loop.process`) | 판정기 |
| checker_full | checker 에서 「고친 줄만 다시 판정」을 끄고 매 회차 문서 전체를 판정 | 판정기 |

- 모든 호출은 구독으로 부른다
- checker 는 판정기 수정안을 그대로 넣는다(세션이 판정기를 따를 때). 1층 지적은 고치지 않는다 — 다른 흐름도 1층을 안 본다

## 측정 1a — 사용자 지적 표현 152건 고침률(자동)

- **입력** — `tests/fixtures/layer2-kinds/carrier.md`(대장 127건과 예비 25건을 심은 운반 문서)
- **흐름** — plain, rules, imnotai, checker 각 1회. 재작성 흐름은 판정기와 같은 절 단위 묶음으로 나눠 부른다(im-not-ai 입력 한도 5,000자)
- **지표**
  - **고침률** — 심은 표현(`text`)이 결과 문서에 글자 그대로 남지 않은 비율. 대장과 예비를 따로 셈
  - **심은 표현이 없는 줄의 변경률** — 지나친 고침을 보는 대조 지표
- **해석 한계** — 1회씩이라 탐색적. 표현을 지웠다고 바르게 고친 것은 아님(뜻 보존은 측정 1b 사람 판정이 봄). 대장 문장은 판단 규칙의 예문이라 rules 와 checker 에 유리 — 예비 25건을 따로 봄

## 측정 1b — AI 업무 문서 사람 판정(사용자 블라인드)

- **입력** — 새로 쓴 AI 업무 문서 6편: 모델 셋(Claude Opus, GPT 6.1 Sol, Gemini 3.8 Flash) × 종류 둘(주간보고, 사내 공지). 가상 회사와 가상 팀만 씀, 문체 지시 없음
- **판으로 내는 것** — 원문, plain, rules, imnotai, rules_loop, checker 여섯 판을 문서마다 무작위 순서와 가명(가~바)으로
- **사용자가 하는 일** — 문서마다 여섯 판의 순위(1이 가장 좋음, 기준은 「AI 투가 없고 업무 문서로 자연스러우며 뜻이 그대로인가」), 판마다 남은 거슬리는 표현 메모(선택)
- **주 지표** — checker 와 다른 판의 일대일 승률(같은 문서 안에서 순위가 높은 비율), 흐름별 평균 순위
- **가름** — 문서가 6편이라 승률 6건 중 5건 이상(83%)이면 「앞섬」, 1건 이하면 「뒤짐」, 그 사이는 「판정 불가」. 미리 정한 기준이며 결과를 보고 바꾸지 않음
- **자동 보조 지표** — 원문 대비 변경률, 1층 오류와 주의 수, `check_meaning --strict` 의 보호 표현 손실, 원문에 없던 「A가 아니라 B」, 「결국」, 「~하는 이유입니다」가 새로 생긴 수

## 측정 2 — 반복 수정 효율(같은 6편)

- **흐름** — rules_loop, checker, checker_full
- **지표** — 회차 수, 호출 수, 환산 비용(구독이라 청구액 아님), 걸린 시간, 사람 확인으로 넘어간 건수, 끝 문서의 1층 오류
- **품질 비교** — rules_loop 와 checker 의 끝 문서는 측정 1b 의 사용자 순위로 견줌. checker_full 은 checker 와 비용만 견줌(끝 문서 품질은 판정기가 같아 비슷하다고 보고 사람 판정에 넣지 않음)
- **가름** — checker 가 rules_loop 보다 비용이나 시간이 6편 중 5편 이상에서 적으면 「효율 앞섬」. checker_full 대비 checker 의 비용 비율 중앙값을 「고친 줄만 다시 판정」의 몫으로 적음

## 바꾸지 않는 것

- 결과를 본 뒤 기준을 고치지 않는다. 바꾸면 그 사실과 까닭을 결과 파일에 적고 탐색적 결과로 부른다
- 측정 도중 판정기 파일을 고치지 않는다
- 문서 본문과 사용자 메모는 저장소 밖 작업 폴더에 두고, 저장소에는 집계만 남긴다
