# 사용자 문체 피드백 반영

**대화에서 받은 수정 요청의 지속 반영** — 원문 보존 · 문서 종류 구분 · 문맥 재작성과 정확 치환 분리

## 처리 흐름

1. **원문 보존**: 사용자가 준 수정 전후 문장을 `user-confirmed-phrases.jsonl`에 그대로 기록
2. **범위 지정**: 발표자 노트·슬라이드·업무 보고·IT 문서 등 적용 문서 종류 기록
3. **문맥 판정**: 독립 문장 여부 · 생략된 조건과 행위 · 실제 계획과 진행 상태 확인
4. **규칙 일반화**: 여러 예시를 묶는 축과 오용 방지 조건을 `user-style-preferences.jsonl`에 기록
5. **회귀 시험**: 예시 개수 · 문맥 필수 표시 · 규칙과 근거 연결 확인
6. **검사 실행**: 데이터 파일을 매번 다시 읽어 코드 수정 없이 새 예시 반영

## 판정 종류

| 종류 | 검사 결과 | 수정 방식 |
|---|---|---|
| 정확 치환 | `suggest_exact` | 확정된 짧은 표현 쌍 제안 |
| 문맥 재작성 | `review_context` | 앞뒤 문장과 사실 상태를 확인한 뒤 재작성 |
| 일반화 후보 | 주의 | 양성·정상 용례 확보 뒤 자동 규칙 검토 |

| 종류 | ❌ 원문 | ✅ 수정문 | 조건 |
|---|---|---|---|
| 정확 치환 | 제품화 경로 | 제품화 단계 | 문구 일치 |
| 문맥 재작성 | 뒤의 것은 커버리지를 더 올립니다 | 더 높은 커버리지를 달성할 수 있도록 개발하고 있습니다 | 현재 개발 중이라는 사실 확인 |

## 우선순위

1. **사용자가 확정한 표현과 범위**
2. **현재 프로젝트의 용어와 문서 종류 규칙**
3. **전역 문서 규칙**
4. **플러그인·자동 지표의 검증 전 후보**

**충돌 처리**: 범위가 좁고 근거가 구체적인 규칙 우선 · 문맥이 다른 예시의 기계적 적용 금지

## 데이터 필드

| 필드 | 값 |
|---|---|
| `feedback_group_id` | 한 번에 받은 피드백 묶음 |
| `scope` | 적용 문서 종류 |
| `register` | 격식과 말투 |
| `axes` | 사용자가 밝힌 수정 기준 |
| `replacement_mode` | 정확 치환 또는 문맥 재작성 |
| `requires_context` | 앞뒤 문장 확인 필요 여부 |
| `standalone_status` | 독립 문장 · 문맥 의존 · 연결절 |
| `context_note` | 정보 보존과 사실 확인 조건 |

## 실행

```powershell
python scripts/scan_user_feedback.py `
  --source <파일-또는-디렉터리> `
  --feedback data/annotations/user-confirmed-phrases.jsonl `
  --output runs/<실행-이름>/user-feedback-findings.jsonl
```

**지원 원본**: Markdown · HTML · 일반 텍스트 · JSON · JSONL · YAML · YML · properties

**출력 위치**: 원본 행 번호를 알 수 있으면 `line_number` · 구조화 문서는 `logical_path`

**출력 원칙**: 자동 수정 없음 · 파일·원본 위치·규칙·수정 제안·문맥 확인 필요 여부 기록
