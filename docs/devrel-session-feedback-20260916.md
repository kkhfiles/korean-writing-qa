# DevRel 제안서 작성 세션의 문체 피드백 — 2026-09-16

**사용자가 한 문서를 고쳐 나가며 낸 지적 전수** — 검사기 규칙 후보로 옮기기 전의 원자료

- **대상 문서**: 사내 AI 활용 공유 행사 제안서 · 본문 6절 + 부록 A~J · 약 600줄
- **독자**: 회사 연구소의 실장들·연구소장 · 대표이사도 공유받음
- **문서 종류**: 회의 제안 자료(개조식) + 사내 공지문 초안(존댓말 산문) + README 양식(템플릿)
- **수집 방식**: 사용자가 직접 지적한 것과, 같은 기준을 문서 전체에 적용해 찾아낸 것을 함께 기록

---

## ⚠️ 이 자료를 규칙으로 옮길 때의 전제

**절대 규칙은 거의 없음** — 아래 항목 대부분은 **같은 낱말이 문서 종류와 위치에 따라 정상과 위반으로 갈림**

| 갈리는 축 | 갈리는 방식 |
| --- | --- |
| **문서 종류** | 회의 자료·보고서에서는 위반 · 구성원에게 말을 거는 공지문·안내문에서는 정상 |
| **위치** | 제목·라벨·표 머리에서는 위반 · 본문 설명에서는 허용되는 경우 있음 |
| **지시 대상** | 실물을 가리키면 정상 · 추상을 가리키면 위반(예: 「조각」이 파일 일부인지 비유인지) |
| **독자** | 같은 설명이 독자에 따라 친절이 되기도 하고 무례가 되기도 함 |

**낱말 목록만으로 자동 판정하지 않음** — 아래 항목은 **「사람이 볼 곳을 좁히는 주의」**가 기본 · 오류로 올릴 수 있는 것은 정상 용례가 실측 0에 가까운 것뿐

**판정 불가일 때는 침묵보다 주의** — 이 목록은 사람이 읽는 검사에 쓰인다. 애매한 것을 지우면 그 줄은 아무도 다시 보지 않는다.

## A. 어휘 — 구어체·비업무 표현

### A-1. 「할지 말지」

- **사용자 지적**: 「할지 말지와 규모는 회의에서 판단」 → 구어체
- **고친 것**: 「**추진 여부**와 규모는 회의에서 판단」
- **같은 기준으로 함께 고침**: 같은 줄의 「그 **모양**과 근거」 → 「그 **구성**과 근거」
- **패턴**: `-ㄹ지 말지` 형태의 양자택일 구어 표현
- **대체어**: 「~ 여부」
- **맥락 의존도**: **낮음** — 업무 문서에서 정상 용례를 찾기 어려움 · 오류 후보
- **반례 확인 필요**: 대화 인용문 안에서는 원문 보존

### A-2. 「쓰다」 계열

- **사용자 지적**: 「각자 **쓰던** 것을 서로 **쓸** 수 있게 모으는 안」 → 구어체이자 업무에서 잘 쓰지 않는 낱말
- **고친 것**: 부제 자체를 삭제(바로 아랫줄이 같은 말을 하고 있었음)
- **같은 기준으로 함께 고침** (문서 전체 8곳)
  - 「이미 **쓰는** 것을 정리해 올리는 것」 → 「이미 **사용 중인** 것을 정리해 제출하는 것」
  - 「동료가 직접 **써 본** 뒤」 → 「동료가 직접 **사용해 본** 뒤」
  - 「**남이 쓸 수 있게** 다듬는 과정」 → 「**다른 사람이 사용할 수 있도록** 정리하는 과정」
  - 「남이 **쓰고 싶게** 설명하는 훈련」 → 「다른 사람이 **사용하고 싶게** 설명하는 훈련」
  - 「이미 **쓰던 것을 꺼내 놓는** 행사」 → 「이미 **사용 중인 것을 정리해 제출하는** 행사」
  - 「업무에 **쓸** 도구를 찾는 일」 → 「업무에 **사용할** 도구를 찾는 일」
- **대체어**: 「사용」·「사용 중」·「적용」
- **맥락 의존도**: **높음**
  - **공지문에서는 그대로 둠** — 「이미 쓰고 계신 것을 정리해 올리는 것이 정식 응모입니다」는 자연스러움
  - **관용구는 그대로 둠** — 「쓸 만하면」·「쓰임」
  - **사용자가 직접 쓴 표현은 그대로 둠** — 「각자 쓰던 것을 꺼내는 행사」는 사용자 원문이라 유지

### A-3. 「모으다」

- **사용자 지적**: 「서로 쓸 수 있게 **모으는** 안」 → 업무에서 잘 쓰지 않는 낱말
- **대체어**: 「수집」·「취합」
- **맥락 의존도**: **높음** — 「의견을 모으다」·「활용 방법이 모이면」은 정상으로 판단해 유지함
- **판정 실마리**: 목적어가 사람의 의견·정보이면 정상 · 산출물·자산이면 재검토

### A-4. 「모양」

- **사용자 지적**: 「아래는 그 **모양**과 근거」 → 업무에서 잘 쓰지 않는 낱말
- **고친 것**: 「그 **구성**과 근거」
- **맥락 의존도**: **높음** — 실제 형태를 가리키면 정상(「글자 모양」·「아이콘 모양」)
- **판정 실마리**: 시각적 형태가 아니라 **구성·구조·방식**을 뜻하면 위반

### A-5. 「머물다」

- **사용자 지적**: 「개인 안에 **머묾**」 → 업무에서 잘 쓰지 않음
- **고친 것**: 「개인이 만들어 사용하는 … 도구가 **조직으로 확산되지 않음**」
- **대체어**: 「확산되지 않음」·「공유되지 않음」·「~ 단위에 국한」
- **맥락 의존도**: **중간** — 물리적 체류(「현장에 머물다」)는 정상
- **주의**: 부정 진술로 바꿀 때 **관찰된 사실과 추론을 가르는 순서**가 함께 걸림 → §D-9 참조

### A-6. 「남」

- **사용자 지적**: 「**남이** 가져다 써서 일이 되게 하는 것이 기준」 → 업무 용어로 부적합
- **고친 것**: 「**다른 구성원이** 받아서 자기 업무에 적용할 수 있는 것이 기준」
- **같은 기준으로 함께 고침** (본문·부록 5곳)
  - 「**남이 따라 할** 수 있는 정도」 → 「**다른 사람이 재현할** 수 있는 정도」 (2곳)
  - 「**남이 받아서 쓸** 수 있어야 함」 → 「**다른 사람이 받아서 실행할** 수 있어야 함」
  - 「최소 자격(업무 관련 · **남이 따라 할 수 있음**)」 → 「(업무 관련 · **다른 사람이 재현 가능**)」
  - 「**남이 쓰고 싶게**」 → 「**다른 사람이 사용하고 싶게**」
- **대체어**: 「다른 사람」·「다른 구성원」·「동료」·「받는 쪽」
- **맥락 의존도**: **높음** — **공지문 3곳은 그대로 뒀음**(「남이 받아서 돌려 볼 수 있어야 평가가 됩니다」) · 말을 거는 글에서는 「남」이 자연스러움

### A-7. 「가져다 쓰다」

- **사용자 지적**: 「남이 **가져다 써서** 일이 되게 하는 것」 → 업무 용어로 부적합
- **같은 기준으로 함께 고침** (4곳)
  - 「**가져다 쓴** 코드·데이터의 권리 확인」 → 「**사용한 외부** 코드·데이터의 권리 확인」 (2곳)
  - 「유사 게이트를 **가져다 맞추면 됨**」 → 「유사 게이트를 **참고해 맞추면 됨**」
  - 「자기 환경에 맞게 **가져다 쓰는** 경우가 많음」 → 「자기 환경에 맞게 **적용하는** 경우가 많음」
- **대체어**: 「사용」·「적용」·「참고」
- **맥락 의존도**: **중간**

### A-8. 「일이 되게 하다」

- **사용자 지적**: 「가져다 써서 **일이 되게 하는** 것이 기준」 → 업무 용어로 부적합
- **고친 것**: 「받아서 **자기 업무에 적용할 수 있는** 것이 기준」
- **패턴**: 추상적 성과를 구어 관용구로 표현
- **맥락 의존도**: **낮음** — 업무 문서에 정상 용례 없음

### A-9. 「혼자 서다」

- **사용자 지적**: 「**혼자 서는** 조각 하나를 떼어 내는 것도 정식 응모」 → 업무 용어로 부적합
- **고친 것**: 「**단독으로 동작하는** 일부 기능만 분리해 제출해도 정식 응모」
- **대체어**: 「단독으로 동작하는」·「독립 실행 가능한」
- **맥락 의존도**: **낮음**

### A-10. 「조각」

- **사용자 지적**: 「혼자 서는 **조각 하나**를 떼어 내는 것」 → 업무 용어로 부적합
- **같은 기준으로 함께 고침** (2곳)
  - 「더 큰 시스템의 **조각이면** 전체를 설명하는 페이지 링크」 → 「더 큰 시스템의 **일부라면**」 (본문·양식 두 곳)
- **대체어**: 「일부」·「일부 기능」·「구성 요소」
- **맥락 의존도**: **중간** — 실물 파편을 뜻하면 정상

### A-11. 「떼어 내다」

- **사용자 지적**: 「조각 하나를 **떼어 내는** 것」 → 업무 용어로 부적합
- **같은 기준으로 함께 고침** (4곳)
  - 「**떼어 내는 작업**은 §4-1의 품질 향상에 해당」 → 「**분리 작업**은」
  - 「별도 시간을 **떼어 낼** 필요 없음」 → 「별도 시간을 **배정할** 필요 없음」
  - 「Basecamp를 만들며 **떼어 냄**」 → 「만들며 **분리**」
  - 「공유를 염두에 두고 **따로 뽑아낸** 저장소」 → 「공유를 염두에 두고 **분리한** 저장소」
- **대체어**: 「분리」·「배정」·「추출」
- **맥락 의존도**: **낮음**
- **주의**: 「시간을 떼어 내다」와 「기능을 떼어 내다」가 **대체어가 서로 다름**(배정 / 분리) · 단순 치환 규칙으로 만들면 오역

### A-12. 「돌아가다」·「돌려 보다」

- **사용자 지적**: 「스킬 하나든 **돌아가는** 도구든 같은 기준으로 봄」 → 업무에서 잘 쓰지 않음
- **고친 것**: 「스킬 하나든 **실행 가능한** 도구든」 (본문·부록 2곳)
- **같은 기준으로 함께 고침** (8곳)
  - **정의된 등급 이름까지 바꿈**: 「**바로 돌아감**」 → 「**바로 실행 가능**」 (본문 표·부록 표 2곳·등급 설명·양식 = 4곳)
  - 「**돌려 보지** 않고도 누를 수 있고, **돌려 보고도** 안 누를 수 있음」 → 「**실행해 보지** 않고도 · **실행해 보고도**」
  - 「발표에서 **돌아가는 것을** 보여야 함」 → 「발표에서 **동작을** 보여야 함」
  - 「전환 직전에 **돌림**」 → 「전환 직전에 **실행**」
  - 「점검 도구를 **돌려 확인**」 → 「점검 도구**로 확인**」 (2곳)
  - 「바로 **돌려 보지만**」 → 「바로 **실행해 보지만**」
  - 「**돌려 보기** 쉽게 함」 → 「**실행해 보기** 쉽게 함」
- **대체어**: 「실행」·「동작」
- **맥락 의존도**: **중간**
  - **「되돌리다」는 다른 낱말** — 「되돌리기 어려움」·「원래 형태로 되돌리는 것이 대안」 4곳은 그대로 둠
  - **공지문 1곳은 그대로 둠** — 「받아서 돌려 볼 수 있어야 평가가 됩니다」
- **기록할 것**: **정의된 라벨·등급 이름도 함께 바꿔야 한다** · 낱말만 고치고 이름을 두면 문서 안에서 어긋남

### A-13. 「누구까지 ~할지」

- **사용자 지적**: 「**누구까지 응모할 수 있게 할지**」 → 구어체
- **고친 것**: 「**응모 자격의 범위**」
- **패턴**: 의문사 + 「~할지」로 만든 라벨 · §B-1(의문문 라벨)과 같은 뿌리
- **맥락 의존도**: **낮음** — 라벨 위치에서는 오류 후보

### A-14. 그 밖에 같은 기준으로 고친 것

| 전 | 후 | 사유 |
| --- | --- | --- |
| 도구 자체가 **좋아짐** | 도구의 **완성도가 올라감** | 평가어의 구어 표현 |
| 선정과 별개로 **따로 골라** | 선정과 별개로 **선별하고** | 구어 동사 |
| 응모자 쪽에 **남는 것** | 응모자의 **역량 성장** | 「부산물」로 읽힘 · 사용자 지적 |
| 상위에 못 들어도 **남는 것이 됨** | 상위에 못 들어도 **도구가 나아짐** | 같은 기준 확산 |
| 공유를 염두에 두고 **따로 뽑아낸** | 공유를 염두에 두고 **분리한** | 구어 동사 |

## B. 라벨과 제목

### B-1. 의문문 라벨 — 검사기가 이미 잡음

- **실제로 걸린 것**: 새로 쓴 절 제목 셋이 검사기 오류로 잡힘
  - 「2-1. **무엇을 받나**」 → 「2-1. **응모물**」
  - 「2-2. **어떻게 선정하나**」 → 「2-2. **선정 방법**」
  - 「2-3. **무엇을 주나**」 → 「2-3. **포상과 발표**」
- **검사기가 못 잡은 것**: **코드펜스 안의 공지문 소제목** 「■ **무엇을 보나**」 → 「■ **심사 기준**」 · 사람이 읽고서야 발견
- **기록할 것**: 코드펜스 안이라도 **실제로 배포되는 문구**(공지문 초안·양식)는 검사 대상이어야 할 수 있음 · 다만 예시 코드와 가르는 방법이 필요

### B-2. 축약한 표 머리

- **사용자 지적**: 「응모 대상 범위에서 **안**? 이 뭐니?」
- **고친 것**: 표 머리 「안」 → 「**응모 가능 대상**」 · 앞 줄 「**안 셋** — 판단 재료는 아래」 → 「**응모 자격의 범위** — 판단 재료는 아래」
- **패턴**: 「안」·「건」·「분」처럼 한 글자로 줄인 표 머리는 무엇의 목록인지 사라짐
- **맥락 의존도**: **낮음** — 표 머리 한정으로 보면 오류 후보

### B-3. 스캔 가치 없는 라벨 — 검사기가 주의로 잡음

- 표 머리 「**내용**」이 두 차례 걸림 → 「**다루는 것**」·「**조건**」으로 고침
- **검사기 판정이 유효했던 사례** · 현행 주의 등급이 적절

## C. 문서 구조

### C-1. 개요는 초록처럼

- **사용자 지적**: 「개요가 뭔가 두괄식으로 잘 읽히지 않는다. 어떤 핵심 페인포인트를 해결하기 위한 이러이러한 것이 주축인 아이디어다. 라고 설명해야하지 않을까? 논문 abstract 처럼?」
- **고친 것**: 행사의 생김새 나열 → **문제 → 방안의 축 → 응모 방식 → 선정 → 포상과 발표 → 공개 범위 → 검토 상태** 순으로 재작성
- **검사기 범위**: 진입점 규칙(§5)의 확장 · 「첫 줄이 문제 진술인가」는 자동 판정 어려움 → **사람이 보는 항목**

### C-2. 결정 요청의 위치

- **사용자 지적**: 「회의에서 정할 것을 위에 두지 맙시다. 아이디어가 어떤지 충분히 설명하고 난 뒤에 괜찮다 또는 해보자 라고 했을 때 정하는게 맞습니다.」
- **고친 것**: §3 「회의에서 정할 것」을 §5로 이동 · 「기대 효과와 위험」을 앞 절로 배치

### C-3. 본문과 부록의 비중

- **사용자 지적**: 「제안하는 자료인데 뭘 할지보다 전체 일정과 기대효과와 회의에서 정할 것의 비중이 대부분이네요?」
- **실측**: 본문 123줄 중 제안 내용은 개요 17줄뿐 · 나머지 106줄이 일정·효과·결정 요청
- **원인**: 상세를 부록으로 내릴 때 **내용을 내리고 메타를 남김**
- **고친 것**: 「행사의 내용」 절(73줄) 신설 — 응모물·선정 방법·포상과 발표·사외 공개
- **기록할 것**: 분량 규칙이 아니라 **「제안 내용 대 메타 정보의 비율」**이 판정 축 · 자동 판정은 어려우나 사람이 보는 점검 항목으로 가치 있음

### C-4. 같은 라벨로 시작하는 줄의 병합

- **사용자 지적**: 「이 두개는 연결된 이야기인데 왜 분리된 문장으로 작성했는지?」
- **걸린 것**: 「**넷째와 다섯째는** 응모자의 역량 성장 — …」과 「**넷째와 다섯째는** 짝 — …」이 나란히 있었음
- **고친 것**: 한 줄로 병합
- **패턴**: **인접한 두 값 슬롯이 같은 어구로 시작하면 분리 오류 신호**
- **맥락 의존도**: **낮음** — 자동 판정 가능성 있음 · 주의 등급 후보

### C-5. 요약 절과 본문의 중복

- **고친 사례**
  - 제목 부제 「각자 쓰던 것을 서로 쓸 수 있게 모으는 안」 삭제 — 바로 아랫줄이 같은 말
  - 개요의 「명칭 후보」 삭제 — 미정 사항 표에 같은 행이 있었음
  - 개요의 「응모 준비에서 남는 것」 삭제 — 기대 효과 표의 넷째·다섯째와 같은 내용
  - 개요의 「구상 개요」 표 6행 삭제 — 개요 본문과 전부 겹침
  - 공지문의 「AI로 채워도 된다」 안내 2곳 → 1곳
- **기록할 것**: 중복 판정에는 **거리**가 변수 · 25줄 안에 같은 내용이 두 번 나오면 하나를 지우는 쪽이 맞음

## D. 내용과 스탠스 — 검사기 범위 밖이나 함께 기록

**문체가 아니라 판단의 문제** · 자동 검사 대상은 아니지만 같은 세션에서 반복해 나온 지적이므로 기록한다.

### D-1. 세일즈 톤

- **사용자 지적**: 「전체적인 스탠스가 이거 무조건 좋고 무조건 해야된다가 아니라 이런 방안이 있고 이런 가치가 있다. 정도였으면 좋겠다. 담백하게.」
- **고친 것**: 「기대 효과 **다섯**」 → 「기대 효과」(세는 행위 자체가 세일즈) · 표 머리 「목표 · **달성 방식**」 → 「기대하는 것 · **그렇게 보는 이유**」 · 서두에 「**다섯이 모두 이루어진다는 전제는 아님**」 추가 · 위험 절 끝에 「**완화해도 남는 것**」 추가

### D-2. 확정처럼 읽히는 미정 사항

- **사용자 지적**

  > 확정은 아닌데 확정처럼 보임 · 후보나 예시라고 써줍시다. 다른 항목도 유사한 맥락에서 검토 [사용자 9/16]

- **고친 것**: 라벨 「명칭」 → 「**명칭 후보**」 · 「일자는 예시」 → 「**아래 일자는 전부 예시** — 어느 날짜도 정해진 것이 아니며」 · 「부록 B. README 양식」 → 「**양식 초안**」 · 흐름표 「**확정** \| 9월 17일」 → 「**제안** \| 9월 17일 · 확정 여부는 미정」 · 절 이름 「**회의에서** 정할 것」 → 「**추진하게 되면** 정할 것」
- **기록할 것**: 라벨에 「후보」·「초안」·「예시」가 붙으면 **값 끝의 「~ 아님」은 중복** · 하나만 남김

### D-3. 소유권 인상을 주는 표현

- **사용자 지적**: 「**회사 이름으로 공개** => 회사 이름이라면 거부감을 가질 수 있음. 회사 깃허브에서 공개 전환 정도로 객관적인 사실만」
- **고친 것**: 「회사 이름으로 공개」 → 「**회사 GitHub에서 공개로 전환**」 (2곳)

### D-4. 오해를 부르는 축약

- **사용자 지적**: 「**비공개로 접수** => 그냥 비공개로 접수라고 쓰면 다른 사람은 못쓰잖아? 라고 이야기가 나올듯」
- **고친 것**: 「비공개로 접수」 → 「**사내 공개**로 접수 — 동료는 열람하고 체험 가능 · 사외에는 비공개」 (문서 전체 9곳)
- **그대로 둔 것**: 보안 협의 항목 3곳 — 거기서 「비공개」는 GitHub의 private 설정을 가리키는 기술 용어

### D-5. 아무도 꺼내지 않은 주제를 부정형으로 적기

- **사용자 지적**: 「**고과 반영은 넣지 않음** => 이런 말은 생각도 안하고 있었기 때문에 넣을 필요도 없다.」
- **고친 것**: 해당 줄 2곳 삭제(인용 포함)
- **패턴**: 「~는 하지 않음」이 **그 주제를 처음 꺼내는 문장**이면 삭제 대상

### D-6. 하나마나한 말

- **사용자 지적**: 「**공개한 뒤에는 되돌리기 어려움 — 복제본까지 회수할 수 없음** => 이것도 당연한 하나마나한 말이 아닌지?」
- **고친 것**: 본문에서 삭제 · 부록에서는 **실제로 놓치는 지점**으로 교체

### D-7. 독자 수준을 낮춰 보는 설명

- **사용자 지적**: 「**파일을 지우고 커밋하면 없어진다고 아는 사람이 많습니다** => 이건 너무 개발자를 무시하고 하는 이야기 아니야?」
- **고친 것**: git 동작 설명 → **실제로 새는 것**(집계·상태·캐시 파일 · 무시 규칙은 추적 중인 파일에 안 먹음 · 이름을 하나만 적으면 변형이 빠져나감)
- **기록할 것**: 같은 문장이 **독자에 따라 친절과 무례로 갈림** · 자동 판정 불가 · 사람이 보는 항목

### D-8. 공감을 얻지 못할 설득 문구

- **사용자 지적**: 「**응모 준비가 자기 도구의 품질을 올린다** => 맞는 말이긴 한데, 공지를 보고 공감을 할까 모르겠다. 공감 못할 내용이면 빼는게 낫다.」
- **고친 것**: 위험 표 2곳과 공지문 블록 4줄 삭제 · 대신 **응모자 입장의 실익**(「서로 받아서 써 봅니다」) 추가
- **기록할 것**: **회의 자료에서 유효한 논리와 공지문에서 유효한 설득이 다름** · 같은 사실을 양쪽에 그대로 옮기면 한쪽이 공허해짐

### D-9. 없는 구분·전제를 만들기

- **사용자 지적 둘**
  - 「연구소 전원인데 왜 개발직군이 아닌 인원이 참여? 연구소는 모두 개발 직군이다.」 → 세 안 중 둘이 같은 것이어서 **둘로 줄임**
  - 진입 장벽 항목 → 해당 단점 삭제

    > 저장소를 다뤄 본 적 없는 인원에게 진입 장벽 => 이정도도 모르면 참여 못하는거다. AI한테 물어봐서 진행할 줄 알아야 한다. [사용자 9/16]

- **기록할 것**: 조직 사실을 모른 채 만든 선택지가 **회의에서 바로 반박됨** · 검사기 범위 밖이나 자료 작성 점검 항목

### D-10. 관찰과 추론의 순서

- **고친 것**: 「개인이 만든 도구가 조직으로 확산되지 않음 · 공유 경로가 세미나 발표에 한정됨」 → **관찰(경로 한정)을 앞, 추론(확산 부재)을 뒤**로 바꿈
- **기록할 것**: 첫 줄이 추론이면 읽는 사람이 근거를 되묻게 됨
