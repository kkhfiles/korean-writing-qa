# 외부 한국어 작성 도구 검토

**외부 한국어 작성 도구의 채택 범위** — 두 저장소의 규칙·검사기를 현재 기준과 AI 원본 표본에 대조

## 결론

- **`korean-report-skills`**: 비교 검사기로 유지 · 자동 치환 규칙은 미채택 · 주어와 술어의 결합 검사 및 식별자 구분 원칙은 후보로 반영
- **`fluent-korean`**: 생성 단계 참고 규칙으로 사용 · 생략된 문장 성분 복원과 비유 억제 원칙 반영 · 문서의 값 칸에는 완전한 문장 규칙 미적용
- **소스 코드 이관**: 없음 · 로컬 복제본은 `data/raw/external/`에 두고 Git에서 제외
- **후보 정본**: `data/annotations/external-rule-candidates.jsonl`

**검사 입력**: `diagnostic-003`의 Markdown 30개 · AI 생성이 메타데이터로 확인된 편집 가능 원본

**실행 조건**: 기본 규칙 120개 · 소프트웨어 문서 결합 규칙 7개 · `--heuristic` 사용 · 자동 수정 미사용

| 결과 | 건수 | 판정 |
|---|---:|---|
| `했다·됐다` 계열의 격식 어미 치환 | 16 | 미채택 · 말투만 바뀌며 자연스러움 개선 근거 없음 |
| `엔드포인트` → `endpoint` | 3 | 미채택 · 세 문장 모두 API 식별자가 아닌 일반 명사 |

## 가져올 원칙

- **주어와 술어의 결합 검사**: `살아 있다` 같은 동사 하나를 금지하지 않고 `session이 살아 있다`처럼 기술 대상과 술어의 조합을 검토
- **식별자와 서술 분리**: 실제 API·enum·필드·모듈 이름은 원형 유지 · 일반 문장은 독자가 아는 표현 사용
- **문장 성분 복원**: `~곳`·`~구간`·`부분`에 숨은 대상과 행위를 복원 · 발표자 노트와 일반 산문에 적용
- **비유의 적용 조건**: 분야에서 굳은 용어는 유지 · 그 밖에는 실제 행위·단계·상황을 명시

## 그대로 쓰지 않을 원칙

- **격식 어미 일괄 치환**: `했다`보다 `하였다`가 더 자연스럽다는 근거 없음
- **한자어·부사 적극 사용**: 정확한 용어 선택에는 도움 · 군더더기와 어려운 말을 늘릴 위험
- **모든 본문의 완전한 문장화**: 일반 산문에는 유효 · 제목·목록·라벨:값의 값 칸과 충돌
- **엠대시 전역 억제**: 현재 규칙은 굵은 결론과 근거를 구분하는 표기로 사용
- **결함을 역량으로 바꾸는 제목**: 사실을 숨기거나 문제의 심각도를 낮출 수 있어 자동 적용 금지
