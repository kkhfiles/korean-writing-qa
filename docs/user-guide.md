# 한글 문서 검사기 사용 안내

**보고서·공유 문서를 내보내기 전에 한국어 표현을 검사하는 도구** — 설치·실행·결과 읽는 법 · 파이썬만 있으면 바로 씀

## 무엇을 잡아 주나

**실제로 걸린 여섯 갈래** — 아래는 검사기를 돌려 나온 결과 그대로다.

| 갈래 | ❌ 걸리는 문장 | ✅ 고친 모양 |
|---|---|---|
| 서술형 종결 | 「개발은 10월 30일에 끝나고 11월 2일부터 테스트가 시작된다」 | **개발 종료**: 10월 30일 · **테스트 시작**: 11월 2일 |
| 절단형 종결 | 「산출물은 해당 폴더에」 | 산출물 → 해당 폴더 |
| 모호한 지칭 | 「우리 제품이 먼저 대응함」 | 그 제품 이름을 그대로 |
| 이중 피동 | 「그렇게 불려지는 이름」 | 그렇게 불리는 이름 |
| 평가 수식어 | 「강력한 검증 엔진 도입」 | 무엇을 하는지로 · 「정적분석 엔진 도입」 |
| 지어낸 명사구 | 「답을 모으는 창은 이틀」 | 답을 모으는 기간은 이틀 |

**그 밖에 보는 것** — 제목과 첫 줄의 형태 · 표 머리의 스캔 가치 없는 라벨(`비고`·`기타`) · 반복되는 묶음에서 라벨이 서로 다른 곳 · 번역투 조사(`현장에서의`)

## 무엇을 안 잡나

**검사기가 조용한 것은 깨끗하다는 뜻이 아니다** — 아래는 사람이 읽어야 한다.

| 안 보는 것 | 왜 |
|---|---|
| 불필요한 영어(`이슈`·`컨펌`·`타깃`) | 문맥에 따라 정당해서 글자로는 못 가름 |
| 사실 관계·수치·인용 | 표현만 봄 |
| 뜻이 통하는지 | 문장의 짜임만 봄 |
| 굵게 개수·줄 간격 같은 시각 서식 | 목적이 「한글이 똑바로 써졌나」 |
| 터미널 화면에 뜬 글 | 파일로 저장된 문서만 대상 |
| PDF·PowerPoint 같은 변환 산출물 | **편집 원본**을 검사할 것 |

## 설치 — 셋 중 하나를 고른다

| 단계 | 받는 것 | 준비 | 고르는 기준 |
|---|---|---|---|
| **1** | `doc-style-check.py` 파일 하나 | **파이썬만 있으면 됨** | 대부분 여기서 충분 · 지적의 대부분이 나옴 |
| 2 | 스킬 폴더 `finalize-korean-document` | Claude Code | 표현 교정까지 맡기고 싶을 때 |
| 3 | 위 + 훅 + 설정 두 줄 | Claude Code 설정 편집 | 문서를 쓸 때마다 자동으로 돌리고 싶을 때 |

**1단계** — 파일을 아무 데나 두고 바로 실행한다. 설치할 라이브러리가 없다(파이썬 기본 모듈만 씀).

**2단계** — 폴더를 통째로 `~/.claude/skills/`에 복사한다.

**3단계** — `~/.claude/settings.json`에 아래 두 항목을 넣는다.

| 시점 | 걸리는 도구 | 나오는 것 |
|---|---|---|
| `PostToolUse` | Edit · Write · MultiEdit | 오류만 · 같은 파일은 한 번 |
| `PreToolUse` | Artifact · Bash · PowerShell | 오류와 주의 전부 |

**막지는 않는다** — 지적을 보여 줄 뿐 저장이나 발행을 멈추지 않는다.

## 쓰는 법

```
python doc-style-check.py <파일 또는 폴더>
```

**여러 개를 한 번에 검사** — 파일과 폴더를 여러 개 나열해도 된다. 폴더를 주면 `.md`와 `.html`을 함께 훑는다.

| 플래그 | 하는 일 |
|---|---|
| `--form prose` | 산문 문서로 보고 개조식 검사를 끔 |
| `--html-only` | HTML만 검사 |
| `-v` | 주의를 여덟 건까지만 접지 않고 전부 보여 줌 |
| `--relaxed` | 굵은 머리 없는 설명 문장을 주의로 낮춤 · 작업 문서 전용 |

**모르는 플래그를 주면 멈춘다** — 오타로 검사가 안 꺼진 채 통과로 읽히는 것을 막는다.

**끝난 뒤 값** — 오류가 있으면 `1`, 없으면 `0`. 스크립트에서 쓸 수 있다.

## 결과 읽는 법

```
── report.md  오류 4 · 주의 2  (값 슬롯 10)
   ❌ [절단형 종결] 8행  산출물은 해당 폴더에 — 조사로 끝나 서술어가 잘렸다
   ⚠️  [평가 수식어] 10행  「강력한」 — - 강력한 검증 엔진 도입
```

| 무게 | 뜻 | 무엇을 할 것 |
|---|---|---|
| ❌ **오류** | 확실한 위반 | **공유 자료는 내보내기 전에 0으로** · 작업 문서는 강제 아님 |
| ⚠️ **주의** | 사람이 봐야 함 | 읽어 보고 정당하면 그대로 둠 |
| ⛔ **검사 불가** | 값 슬롯을 못 찾음 | **합격이 아니라 안 본 것** · 표나 목록으로 다시 씀 |

**값 슬롯 수를 함께 본다** — 분량에 비해 슬롯이 적으면 검사기가 그 문서를 거의 못 본 것이다.

## 꼭 알아 둘 것 하나 — 산문 문서

**개조식을 전제로 검사한다** — 표와 라벨이 뼈대인 업무 문서 기준이다. 소개 글·설명문·발표 대본처럼 **흐르는 문장이 뼈대인 문서**는 형식을 적어야 한다.

| 형식 | 적는 곳 |
|---|---|
| 마크다운 | 머리말에 `form: prose` |
| HTML | `<meta name="form" content="prose">` |

**파일이 형식을 들고 있게 한다** — 플래그로만 주면 검사할 때마다 기억해야 한다.

**안 적고 산문을 검사하면** 검사기가 한 줄로 물어본다. 그때 적으면 된다.

## 오탐이 나오면

**정당한 문장인데 걸렸다면 고치지 않는다.** 그 문장과 왜 정당한지를 알려 주면 규칙에 예외로 넣는다.

**혼자 판단하지 말 것 둘** — 아래는 오탐처럼 보여도 대개 진짜다.

| 지적 | 대개 진짜인 까닭 |
|---|---|
| 「우리」 지적 | 부서가 섞여 보는 문서에서는 가리키는 것이 사람마다 다름 |
| 표 머리 「비고」 | 공문서 관례라 오류가 아닌 **주의**로만 나옴 · 막지 않음 |
