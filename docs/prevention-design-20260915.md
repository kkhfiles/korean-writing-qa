# 재발방지 설계안 — 탐지 넷과 호출 하나

**이 문서로 정하는 것** — 한글 결함이 사용자에게 여섯 차례 발견된 원인을 층별로 막는 설계 · 2차 수정(GPT-6 검토 반영) · 실행 전

**읽고 나면 아는 것** — 탐지 넷이 각각 못 잡은 까닭 · 호출 경로의 한계 · 고칠 일곱 가지와 측정 기준 · 검토에서 뒤집힌 것

|---|---|---|---|
| 1 | 2026-08-29 이전 | `자리` | 공개 소개 페이지 |
| 2 | 2026-08-29 | `판` · `창` | 공개 소개 페이지 |

## 2. 진단

### 2-1. 탐지는 넷 · 안내는 탐지가 아님

⚠️ **첫 진단의 「다섯 겹」은 틀린 셈**(GPT-6 검토 ①). 1층 구조 검사와 1층 낱말 규칙은 같은 실행체 안에 있고, 안내는 판정을 하지 않습니다. 바로 세면 **탐지 넷과 호출 경로 하나**입니다.

| 갈래 | 실행체 | 6회차 결과 |
|---|---|---|
| 탐지 1 · 구조 | `doc-style-check.py` | 오류 **0건** |
| 탐지 2 · 낱말 | 같은 실행체의 `NO_WORK_WORD` | **0건** — 고정 짝 목록 |
| 탐지 3 · 빈도 | `rare_words.py` | **안 돌았음** — 어디에도 안 걸림 |
| 탐지 4 · 판단 | 2층이 `core-rules.md` 를 읽음 | **안 불렸음** · 불려도 원칙 없음 |
| 호출 경로 | `finalize_notice()` | `PreToolUse` 밖이면 즉시 반환 |

### 2-2. 문서 둘에서 같은 무늬 (검토 ① 에 대한 답)

**재측정** — 문서 하나로 일반화했다는 지적을 받고 다른 회차 원문에도 댔습니다.

| 지적 전 원문 | 분량 | 탐지 1 | 탐지 2 | 탐지 3 이 올린 것 |
|---|---|---|---|---|
| 3·5회차 사례집 | 637,355자 | 오류 0 | 0건 | 142종 · `굳` 포함 |
| 6회차 구상서 | 11,753자 | 오류 0 | 0건 | 58종 · `굳`·`깎`·`싣` 포함 |

- **되풀이 확인** — 분량이 54배 차이 나는 두 문서에서 탐지 1·2 가 똑같이 침묵했습니다.
- ⚠️ **탐지 3 도 `갈래` 는 못 잡음** — 90회로 문턱 40 위입니다. 빈도 하나로는 안 닫힙니다.

### 2-3. 실행율 — 분모를 갈라 적음

⚠️ **첫 진단이 분모를 섞음**(검토 ①) · 갈라 적으면 아래와 같습니다.

| 재는 것 | 값 | 분모 |
|---|---|---|
| 안내 발화율 | 20.2% | 발행 258회 중 안내 52회 |
| 안내 이행율 | **3.8%** | 안내 52회 중 스킬 실행 2회 |
| 발행 대비 실행율 | **0.78%** | 발행 258회 중 스킬 실행 2회 |

### 2-4. 확정한 사실

- **훅 25개 전부 있고 돎** — rc 0 · 파일 누락 0
- **CI 는 푸시마다 돌고 통과** — 시험·자체검사·발행안전 포함
- **1층 게이트 정상** — Write·Edit·MultiEdit × 저장소 안팎 × md·html 열두 가지 모두 지적
- **2층 안내가 뜨는 곳 셋** — Artifact · 노션 · Marp
- **2층 회수율 0.771 · 1층 0.057** — 능력이 아니라 호출이 문제

### 2-5. 첫 진단에서 뒤집은 것

| 처음 적은 것 | 실측 |
|---|---|
| Edit 에는 게이트가 조용함 | 틀림 — 같은 파일을 두 번 먹인 시험 탓(「파일당 세션 1회」) |
| 발행 경로 열셋 중 아홉 누락 | 과장 — Artifact 는 걸려 있음 · 실제 누락 넷 |
| 2층이 돌기만 하면 잡았을 것 | 틀림 — 규칙집에 그 원칙 없음 |
| 다섯 겹이 각각 비켜 감 | 틀린 셈 — 탐지 넷 · 호출 하나 |
| 2층 실행율 3.8%(발행 대비) | 분모 혼동 — 발행 대비는 0.78% |

⚠️ **같은 함정에 세 번 걸림** — 게이트의 「파일당 세션 1회」 상태를 공유하는 시험을 세 번 짰습니다. 설계에 반영한다(「상태를 쓰는 검사의 시험용 통로」 절).

## 3. 설계

### 3-0. 발행을 두 모양으로 가름 — 처방이 갈리는 지점

| 모양 | 보기 | 막는 방법 |
|---|---|---|
| **명령으로 나감** | 노션·Marp·Artifact·git push·메일·슬랙 | **차단 가능** — 「명령 발행」 절 |
| **파일을 쓰는 것이 곧 발행** | 공유 폴더 · `D:/DevRel` · NAS | **차단 불가** — 문서를 못 쓰게 할 수 없다 · 「파일 쓰기가 곧 발행인 경로」 절 |

**6회차는 둘째 모양** — 첫 진단이 이 구분을 안 해서 처방 하나로 둘을 덮으려 했습니다.

### 3-1. 명령 발행 — 내용 해시에 묶인 검사 결과가 없으면 **차단**

**받은 제안** — 검토 ③ · 안내가 아니라 허용 조건을 바꿉니다.

| 단계 | 하는 일 |
|---|---|
| 검사 통과 시 | `{문서 해시, 규칙 버전, 판정, 시각}` 을 기록 |
| 발행 명령 앞 | 그 파일의 **지금 내용 해시**로 기록을 찾음 |
| 기록 없음·해시 불일치·오류 | **발행 보류**(`PreToolUse` 거부) |

- **해시로 묶는 까닭** — 옛 판을 검사한 뒤 고쳐서 내보내는 길을 막습니다. 검토 ③ 이 짚은 구멍입니다.
- **비용** — 변경본 N개에 판정 N회 · 발행 지연 · 발행 경로 통합 공수
- **⛔ 오탐의 대가는 발행 보류** — 보류 비용을 먼저 재고, 사람이 푸는 길(`--force-publish` + 사유 기록)을 같이 둡니다.

### 3-2. 파일 쓰기가 곧 발행인 경로 — 안내 대신 **정지**

- **차단할 수 없는 까닭** — 문서를 쓰는 행위 자체를 막을 수 없습니다.
- **쓸 수 있는 유일한 지렛대** — 응답을 끝내지 못하게 하는 것(`Stop` 훅의 `decision: block`)
- **지금과 다른 점** — 안내는 읽고 넘길 수 있지만 정지는 못 넘깁니다. 검토 ④ 가 짚은 「같은 LLM 의 자발적 이행에 의존」이 여기서 끊깁니다.

✅ **전제 확인 완료** [2026-09-16] — 공식 문서에 `Stop` 은 막을 수 있고, 막으면 **「Claude 가 멈추는 것을 막고 대화를 이어 간다」**고 적혀 있다. 종료 코드 2 또는 `decision` 으로 낸다.

⚠️ **반복 방지 장치를 직접 만들어야 함** — 이 판의 `Stop` 입력 스키마에 `stop_hook_active` 가 없습니다. 무한 반복을 막을 표준 깃발이 없으므로 **`prompt_id` 당 한 번만 막습니다**(입력에 그 값이 있습니다). 두 번째 `Stop` 에서는 막지 않고 **놓친 것으로 기록**합니다.

- **자가 제한이 반드시 먼저** — 막기만 하고 풀 길이 없으면 세션이 못 끝납니다. `prompt_id` 상태 기록을 먼저 만들고 그 위에 막기를 얹습니다.

### 3-3. 완료 판정은 「최종 내용 + 검사 결과」로

**받은 지적** — 검토 ② 의 넷째.

- **⛔ 스킬을 시작한 것으로 완료 처리하지 않음** — 실패·중단도 완료로 세어집니다.
- **완료로 치는 조건** — 그 파일의 **최종 내용 해시**에 대해 검사가 **통과**로 끝난 기록
- **전역 규칙과 같은 모양** — 「성공으로 기록됨 ≠ 일을 마쳤음」 · 시작 신호와 종료 산출물을 같은 단위로 대조

### 3-4. `core-rules.md` 에 빈도 원칙 추가

**넣을 원칙**

> **업무에서 쓰는 말로 쓰기** `[탐지1: 고정 짝]` `[탐지3: 새 낱말]` `[2층: 짝 판정]`
> 가르는 기준은 어원이 아니라 **빈도**다. 드물게 쓰는 고유어는 흔한 한자어보다 어렵다.
> **한 낱말로 있는 행위 명사를 동사구로 풀지 않는다** — 구분을 「갈라서 냄」으로, 통합을 「열어 합치기」로, 입력을 「공수 넣기」로 푼 것이 그 예다.
> **판정** — 그 구를 한 낱말로 바꿔 보고, 바뀐 쪽이 업무 문서에서 더 자주 보이면 그쪽이 맞다.

- **2층에 꼭 넣어야 하는 까닭** — `공수 넣기` 는 쓴 동사가 흔해 빈도로 안 걸린다(검토 ① 의 반례). 탐지 3 이 놓치는 것을 2층이 받는 구조여야 합니다.
- **표시 이름 교체** — 지금 `[사람]` 은 「2층이 본다」는 뜻인데 「사용자가 본다」로 읽힙니다. `[2층]` 으로 바꾸고 대장의 주인 이름도 같이 바꾼다(`사람` → `2층` · 11건).

### 3-5. 2층 절차에 단어 점검 편입

- **지금** — `scripts/rare_words.py` 는 새 낱말을 잡는 **유일한** 기계인데 스킬·훅·CI 어디에도 없음
- **넣을 위치** — `finalize-korean-document` 작업 순서의 1층 검사 다음
- **⚠️ 지금 그대로 넣으면 실패** — 문서당 출력 23줄 중 건질 것이 1~3줄입니다. 나머지는 이 분야 용어(`개조`·`명사`·`피동`)다. 오탐이 섞인 목록은 곧 아무도 안 봅니다. 「본 단어 기억」 절이 먼저입니다.

### 3-6. 본 단어 기억 — 낱말이 아닌 **짝** 단위

**받은 지적** — 검토 ① 의 마지막. 낱말 전체를 정상으로 등록하면 그 낱말이 나쁘게 쓰인 경우까지 영영 가려집니다.

```
python -X utf8 scripts/rare_words.py <문서> --seen data/catalog/known-words.jsonl
python -X utf8 scripts/rare_words.py --accept 갈래 --context "두 갈래 길" --why "실제로 나뉘는 대상"
```

| 항목 | 값 |
|---|---|
| 기록할 것 | 단어 · 품사 · 허용 문맥 · **적용 범위** · 날짜 · 근거 한 줄 |
| 등록 28개 시점 · 이 저장소 문서 | 71 → 68 · 42 → 33 · 82 → 69 (**11~21% 감소**) |
| 등록 28개 시점 · 바깥 문서(대조군) | 58 → 58 (**0** — 범위가 제대로 갈림) |

⚠️ **「1~3줄」은 아직 추정치** — 등록 28개로는 11~21% 줄었습니다. 목록이 쓰면서 자라야 닿는 수치이고, 그 전까지는 그렇게 적지 않습니다.

**범위가 왜 꼭 필요한가** `[2026-09-16 실측]` — 목록을 채우는 낱말을 세어 보니 소음이 아니었습니다. 명사 12 · 동사 9 · 문단 11 · 비유 11 로 **사람 글에서 진짜 드문 말**이다(업무 말뭉치에 문법 용어가 없다). 낱말만 열어 주면 업무 보고서에 같은 말을 써도 안 걸립니다.

- **범위를 넓힐수록 소음 감소** — 모든 문서에 돌리면 목록이 빨리 차서 새 낱말만 남습니다. 좁게 쓰면 목록이 안 자라 매번 같은 23줄을 봅니다.
- **⛔ 문맥 없는 등록 금지** — 「`갈래` 는 정상」으로 넣으면 「갈래 ① 변경 요청 단계」까지 통과합니다.

### 3-7. 상태를 쓰는 검사의 시험용 통로

- **발단** — 게이트의 「파일당 세션 1회」 때문에 같은 파일로 두 번 재면 둘째가 조용합니다. 이것을 「Edit 를 안 본다」로 **세 번** 잘못 읽었습니다.
- **넣을 것** — `--probe` 를 주면 상태를 읽지도 쓰지도 않고 판정만 냄

## 4. 안 하기로 한 것

| 안 하는 것 | 근거 |
|---|---|
| 낱말을 규칙에 하나씩 추가 | 여섯 차례가 그 방식으로 실패 · 일곱째 낱말을 못 막음 |
| 명사 덩어리 검출기 | 이미 만들어 기각 — 정밀도 15~55% · 회수 1/3 |
| 단어 점검 문턱을 40 → 100 으로 상향 | 지적 56% 증가 · 얻는 것은 경계선 단어 하나 |
| 프롬프트에 경고 한 줄 추가 | 2026-09-09 에 시행 · 그 뒤로 세 차례 더 발생 |
| 안내 문구를 더 크게·자주 | 검토 ④ 의 지적 — 위치만 바꾼 같은 방식 |
| 전역 규칙 「짧고 쉬운 말」 절 전체 삭제 | 군더더기·단문·중복 규칙은 이번 실패와 무관 |

## 5. 측정 계획

**지표 교체** — 검토 ④ 의 제안. 실행율은 **수단**이지 결과가 아닙니다.

| 무엇 | 기준선 | 재는 법 |
|---|---|---|
| **최종본의 발행 전 검사 완료율** | 미측정 | 발행된 내용 해시 중 통과 기록이 있는 비율 |
| **발행 100건당 잔존 결함** | 미측정 | 사용자 지적 + 사후 단어 점검 |
| 안내 이행율 | 3.8% | 수단 지표 · 참고용 |
| 1층 회수율 | 0.057 | 안 바꿈 · 대조군 |

⚠️ **실패를 인정하는 조건** — 2주 뒤 **발행 전 검사 완료율이 50% 미만**이면 「파일 쓰기가 곧 발행인 경로」 절이 틀린 것입니다. 안내를 키우는 쪽으로 가지 않고 **사람 호출에 의존하지 않는 구조**를 다시 설계합니다.
