## 사람이 쓴 업무 문서와 비교함

- **얻는 것**: 업무 문서에서 드물게 쓰는 단어를 검토 후보로 받음
- **기술 요소**:
  - 단어 점검(`scripts/rare_words.py`) — 사람이 쓴 업무 문서의 단어 빈도표와 비교해 드문 단어를 후보로 제시함, 고칠지는 판정기와 사람이 결정
  - 규칙마다 실문서에서 건수를 집계한 뒤 추가 — 정당한 쓰임이 섞이면 등급을 주의로 낮춤
  - 규칙의 판단 기준은 글의 품질 — 빈도는 판단을 돕는 참고 자료이고, 「사람이 많이 쓴다」는 이유만으로 규칙에서 빼지 않음
- **근거**:
  - 기준 자료 — 사람이 쓴 업무 문서 36,037편, 4,793만 자
  - 규칙 실측 대상 — 사내 보고서 600여 개, 문서 형식과 무관하게 적용되는 오류 유형에 걸린 문서 8%(개조식 규약까지 켜면 33%)
- **문구 후보**: 「사람이 쓴 업무 문서 4,793만 자와 비교해, 업무 글에서 드물게 쓰는 단어를 검토 후보로 제시합니다.」

## 글자 모양으로 판별하는 검사와 문맥을 읽는 판정을 나눔

- **얻는 것**: 글자 모양으로 판별되는 위반은 검사기가 즉시 검출하고, 문맥을 봐야 판별되는 표현은 판정 모델이 읽어서 검출함
- **기술 요소**:
  - 1층 검사기(`assets/doc-style-check.py`) — 파이썬 파일 하나, 검사 유형 묶음은 문장 끝맺음, 낱말 선택, 번역투, 구조, 안내(형식을 적지 않은 문서에 형식 선언을 요청하는 안내 한 줄)이고 이름은 검사기 출력 그대로
  - 형태소 분석(`kiwipiepy`) — 「보내는 때」의 관형형 어미와 「이제는 때가 됐다」의 보조사처럼 글자가 같은 형태를 품사로 구분함
  - 2층 판정기(`scripts/judge_layer2.py`) — 문서의 한글 줄마다 판정하고, 판정 원칙(`core-rules.md`), 사용자가 확정한 수정 표, 그 문서의 드문 단어 목록, 개인 판정 기준을 함께 받음
  - 판정 모델 — Claude Code 환경은 Opus, Codex 환경은 OpenAI 모델(기본 별칭 `sol-high`)
- **근거**:
  - 회수율(실제 문제 가운데 검출한 비율) — 1층 0.057, 2층 0.771(`runs/eval-005`, 문서 3건 전수 판정)
  - 2층 정밀도(2층 지적 가운데 실제 문제인 비율) — 0.80~0.85(같은 측정, 사용자 판정 기준)
  - 1층 오탐 — 정상 시험 문장 34건에서 0건
  - 한계 — 실제 문제 35건 표본이라 신뢰 구간이 넓음
- **문구 후보**: 「글자 모양으로 판별되는 위반은 검사기가 문서 전체에서 검출하고, 문맥을 봐야 판별되는 표현은 판정 모델이 읽어서 검출합니다.」

## 발행을 막되 해제 방법을 함께 둠

- **얻는 것**: 검사를 거치지 않은 문서는 발행되지 않고, 오탐 때문에 작업이 멈추지도 않음
- **기술 요소**:
  - 훅 두 시점 — 파일을 고칠 때 오류를 바로 알리고, 발행 명령 직전에 오류와 주의를 전부 출력함
  - 통과 기록(`scripts/check_record.py`) — 문서 내용의 해시에 묶임, 한 글자만 고쳐도 다시 검사
  - 주의 판단 기록 — 어떤 주의를 왜 정상으로 판단했는지 적어야 통과, 오류에는 적용 안 됨
  - 판정기 지적의 처리 — 수정, 근거를 대고 반영하지 않음, 사람 확인으로 올림 중 하나로 처리해야 발행
  - 근거 대조 — 반영하지 않는 근거로 인용한 문구가 근거에 적은 파일에 글자 그대로 있는지 확인
  - 재판정 상한 — 같은 줄을 세 번 넘게 다시 판정하면 사람 확인으로 넘어감
  - 사이트 배포 — 배포 명령을 실행할 때 배포 원본마다 같은 검사
- **근거**: 2026-09-16 해제 방법 없이 발행을 막아 모든 발행이 멈춘 뒤, 발행을 막는 지점마다 해제 방법과 해제 기록을 함께 두도록 고침
- **문구 후보**: 「검사를 거치지 않은 문서는 발행되지 않습니다. 오탐으로 판단한 지적은 사유를 기록하면 반영하지 않을 수 있습니다.」

## 고친 문장을 다시 고치는 일을 줄임

- **얻는 것**: 한 번 판정하고 고친 줄을 판정기가 거듭 지적해 같은 줄을 여러 번 고치는 일이 줄어듦
- **기술 요소**:
  - 바뀐 줄과 새 줄만 판정 — `--since <기준>` 으로 바뀐 줄과 새 줄만 다시 판정하고, 나머지 줄은 문맥으로만 읽음
  - 고치기 전후 대조 — 다시 판정할 때 고치기 전 줄과 지운 줄을 함께 받아, 고친 말이 뜻을 바꿨는지 대조함
  - 닫은 지적 전달 — 세션이 근거를 대고 닫은 지적을 다시 판정할 때 함께 받아, 같은 지적을 반복하지 않게 함
  - 답대로 고친 줄 확정 — 사용자 답대로 고친 줄은 사람이 판정한 줄로 기록하고 다시 판정하지 않음
  - 사용자 답 재사용 — 「그대로」 답과 확정 수정 표를 판정기가 매번 읽음
  - 재판정 상한 — 같은 줄을 세 번 넘게 다시 판정하면 판정기 대신 사람 확인으로 넘김
- **근거**:
  - 2026-10-12 — 근거를 확인해 닫은 지적을 줄이 바뀐 뒤 판정기가 다시 냄, 이후 닫은 지적을 재판정 입력에 넣음
  - 2026-10-14 — 판정기가 출처 소개 한 줄을 사람 확인으로 네 번 올림, 이후 답대로 고친 줄을 확정하도록 고침
  - 한계 — 재수정 횟수가 얼마나 줄었는지 측정한 자료는 아직 없음
- **문구 후보**: 「고친 문서를 다시 판정할 때는 바뀐 줄과 새 줄만 판정하고, 고치기 전 문장과 이미 내린 판정을 함께 읽습니다.」

## 공유받은 사람이 자기 규칙을 더함

- **얻는 것**: 공유받은 사람이 공통 규칙은 그대로 받으면서 자기 조직이나 자기 글의 기준을 더하고, 필요 없는 검사 유형은 끔
- **기술 요소**:
  - 개인 낱말 목록(`local-personal-words.tsv`) — 「결함을 잡다 → 검출」처럼 동사와 바꿀 말을 적으면 1층 검사기가 주의로 냄
  - 개인 판정 기준(`local-layer2-rules.md`) — 용어 정의나 조직의 문서 관례를 글로 적으면 2층 판정기가 판정할 때마다 판정 원칙 뒤에 붙여 읽음(2026-10-29)
  - 제품 이름 목록(`local-brand-names.txt`) — 자사 제품 이름과 잘못 적은 꼴을 적으면 1층 검사기가 잘못 적은 꼴을 오류(제품 이름 음차)로 냄
  - 조직 설정(`korean-qa.toml`) — 검사 유형을 끄거나 등급을 올리고 낮춤, 발행 게이트는 설정과 무관하게 모든 유형을 검사함
  - 보관 위치 — 개인 파일은 공개 저장소에 올라가지 않고, `install.py` 가 설치 폴더로 복사해 다른 프로젝트의 검사에도 적용함
- **근거**:
  - 2026-10-29 — 개인 낱말 목록을 설치 폴더로 복사하지 않아 저장소 밖 문서에는 적용되지 않던 결함을 재현하고 고침, 설치 과정에서 검사기가 읽는 개인 파일이 복사되지 않으면 실패하는 시험을 추가함
  - 개인 판정 기준은 판정기 성능을 측정할 때 `KOREAN_QA_LOCAL_RULES=off` 로 제외할 수 있음
- **문구 후보**: 「공통 규칙은 그대로 받고, 자기 조직의 용어와 문서 관례는 파일 하나에 적어 판정에 더합니다.」

## 사람이 내린 판정을 규칙에 반영함

- **얻는 것**: 한 번 지적한 표현마다 다음 문서에서 그 표현을 맡을 검사나 판정 기준이 정해짐
- **기술 요소**:
  - 지적 대장(`data/cases/flagged-rounds.jsonl`) — 사람이 지적한 표현마다 처리 담당(규칙, 단어 점검, 사람, 대기)을 적음, 담당이 비면 시험 실패
  - 사람 확인 판정표(`scripts/ask_sheet.py`) — 판정기가 문제인지 판별하지 못한 지적을 「원문을 고칠까요?」 하나로 묻고 고침, 그대로, 직접 고침, 보류 중 하나로 답을 받음
    - 칸 — 원문, 고친 말, 고친 이유, 세션 의견, 답(2026-10-28 사용자가 정한 형식)
    - 짧은 답 — 「전부 의견대로」, 「의견대로, 단 3 그대로」처럼 답하면 각 행의 답을 세션 의견 칸 내용으로 채움, 의견 칸이 빈 행이 하나라도 있으면 짧은 답 전체를 받지 않음
    - 화면 판정표 — 버튼으로 고르고 짧은 답을 복사하는 HTML 판정표(시안 검토 중)
    - 아직 구현하지 않은 것 — 규칙을 새로 추가할지 묻는 확인은 이 판정표를 거치지 않음
  - 답의 재사용 — 받은 답을 다음 판정의 프롬프트에 실음
  - 확정 수정 표 — 사용자가 확정한 수정을 판정기가 매번 읽음
  - 같은 유형 전수 수정 — 지적한 표현과 같은 유형을 저장소 전체에서 찾아 고침
- **근거**: 지적 대장 201행, 회귀 시험 데이터 77건(2026-10-28)
- **문구 후보**: 「지적해 주신 표현은 지적 대장에 올리고, 같은 유형을 찾아 고친 뒤 검사 규칙, 단어 점검, 판정 기준 가운데 그 표현을 담당할 항목을 정합니다.」

## 지적이 없는 결과를 합격으로 보지 않음

- **얻는 것**: 「오류 0」이 실제 통과인지, 검사기가 검사하지 못한 것인지 구분됨
- **기술 요소**:
  - 판정 결과 세 종류 — 오류, 주의, 검사 불가(값 칸을 찾지 못한 파일, 값 칸은 표 칸과 목록 항목처럼 검사기가 검사하는 단위)
  - 검사한 값 칸 수 함께 출력 — 분량에 비해 적으면 검사기가 그 문서를 거의 검사하지 못한 것
  - 끈 유형 표시 — 설정으로 끈 유형을 결과 맨 위와 합계에 적음
  - 형태소 분석기 부재 표시 — 없으면 일부 유형을 글자만으로 좁게 검사했다는 사실을 출력에 적음
  - 판정하지 않은 줄 차단 — 판정기가 아직 판정하지 않은 한글 줄이 남으면 발행을 막음
- **근거**: 2026-09-21 문서 판본 129개에 판정 기록이 0건이었던 원인이 「표본 부족」이 아니라 기록 명령 누락으로 드러남, 이후 판정 기록이 저장되는지 확인하는 시험을 추가함
- **문구 후보**: 「검사하지 못한 문서는 통과가 아니라 '검사 불가'로 표시합니다.」

## 정상 문장은 지적하지 않음

- **얻는 것**: 지적이 지나치게 많지 않아 결과를 끝까지 읽게 됨
- **기술 요소**:
  - 문서가 형식을 선언 — 머리말 `form: prose`(소개 글, 발표 대본)는 개조식 전제 검사를 끄고, `form: app`(업무 화면)은 문서 뼈대 검사만 끔
  - 긴 머리말 지원 — Marp 슬라이드처럼 CSS를 넣어 길어진 머리말도 끝까지 읽음(2026-10-28)
  - 조직 설정(`korean-qa.toml`) — 유형을 끄거나 등급을 낮춤, 발행 게이트는 설정과 무관하게 모든 유형을 검사함
  - 검사 제외 구간 — 「」 인용, 코드, ❌ 대조 예시
  - 새로 쓴 줄만 검사하는 규칙 — 띄어 쓴 가운뎃점 규칙에 적용, AI 세션이 문서를 처음 고치기 직전의 줄을 훅이 대장에 기록하고 그 뒤 새로 생긴 줄에서만 위반을 오류로 표시함
  - 밀집 조건 — 「~에 대해」처럼 한 번은 정상인 형태는 한 문단에 3회 이상 나올 때만 지적함
- **근거**:
  - 산문 문서 73편 — 형식 선언 뒤 문서당 오류가 13.51건에서 1.10건으로 감소(`runs/diagnostic-004`)
  - 짝 시험 문장 — 정당한 표기 20종과 같은 모양의 위반 15종을 함께 시험
  - AI 글 윤문 도구 im-not-ai에서 도입한 규칙의 오탐 — 새로 추가한 규칙마다 사람이 쓴 문서 284편 중 지적된 문서 비율 2.5% 이하(`docs/imnotai-coverage-20261023.md`)
- **문구 후보**: 「소개 글과 발표 대본은 머리말 한 줄로 개조식 검사를 끕니다. 위반과 모양이 같지만 바르게 쓴 표기 20종을 지적하지 않는지 시험으로 확인합니다.」

## 설치한 PC의 모든 프로젝트에 같은 검사를 적용함

- **얻는 것**: 이 저장소 밖의 프로젝트와 다른 PC에서도 같은 검사가 적용됨
- **기술 요소**:
  - 설치(`install.py`) — 검사기, 스킬, 훅을 설치하고 `--check` 로 원본과 대조
  - 두 에이전트 지원 — Claude Code와 Codex가 같은 훅을 씀(Codex는 어댑터가 도구 이름을 변환함)
  - 매일 점검 — 하루 첫 세션에 설치본 대조, 커밋 안 한 변경, 푸시 안 한 커밋, 마지막 CI 결과를 확인하고 문제가 없으면 아무것도 출력하지 않음
  - 적은 의존성 — Python 3.11 이상, 검사기는 표준 모듈만으로 동작하고, YAML 검사와 형태소 판정에만 외부 패키지(PyYAML, kiwipiepy)가 필요함
- **근거**: 설치본을 직접 고치면 `tests/test_installed_copy_matches.py` 가 실패
- **문구 후보**: 「설치 명령 하나로 Claude Code와 Codex 양쪽에 같은 검사가 적용됩니다.」

## 검사기 자체를 시험함

- **얻는 것**: 규칙을 고쳐도 검출하던 것을 놓치지 않음
- **기술 요소**:
  - 짝 시험 — 규칙마다 검출할 문장과 검출하면 안 될 문장을 함께 둠
  - 결함 주입 확인 — 규칙 코드에 의도적으로 결함을 넣어 시험이 검출하는지 확인
  - 알려진 실패 기록 — 해결하지 못한 결함을 검출하는 시험을 삭제하지 않고, 무엇이 왜 실패하는지와 함께 기록함
  - README 예상값 시험 — README에 적은 출력값을 실제로 실행해 대조
  - CI — 푸시마다 전체 시험
- **근거**: 시험 파일 126개, 시험 함수 1,066개(2026-10-28)
- **문구 후보**: 「규칙마다 검출할 문장과 검출하면 안 될 문장을 짝으로 시험합니다. 규칙 코드에 의도적으로 결함을 넣어 시험이 검출하는지도 확인합니다.」

## 공개 전에 이력 전부를 검사함

- **얻는 것**: 공개 저장소에 사람 이름, 고객사, API 키가 유출되지 않음
- **기술 요소**:
  - 공개 안전 검사(`scripts/check_publish_safety.py --history`) — 지금 파일뿐 아니라 커밋 이력 전부를 검사함
  - 신원 목록 분리 — 걸러 낼 실명과 고객사 목록을 저장소 밖에 둠, 코드 안에 실명과 고객사 이름이 담기지 않게 함
  - 푸시 게이트 훅 — 공개 저장소로 푸시하기 직전에 같은 검사
- **근거**: 지운 파일도 공개 저장소의 이전 커밋에서 내려받을 수 있으므로, 유출은 올리기 전에 막아야 함
- **문구 후보**: 「공개 저장소로 내보내기 전에 지금 파일뿐 아니라 커밋 이력 전부를 검사합니다.」
